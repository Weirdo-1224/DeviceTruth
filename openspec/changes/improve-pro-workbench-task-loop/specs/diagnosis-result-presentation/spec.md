# Spec Delta

## Purpose

让诊断结果先回答当前结论、下一步和直接候选原因，同时保留完整证据与原文，避免背景观测因排列顺序被误认为主要故障判断。

## ADDED Requirements

### Requirement: 结构化判断业务语义
每条结构化判断 SHALL 提供业务类型和目标相关性，至少区分候选原因、观测、结论、其他及未知。系统 MUST NOT 根据确定性或关键词推断业务类型与相关性。

#### Scenario: 新答案包含直接候选原因
- **WHEN** 模型形成候选原因答案并提交结构化判断
- **THEN** 每项判断带有受控业务类型与相关性，直接候选原因可与其他观测明确区分

#### Scenario: 判断字段矛盾或不受控
- **WHEN** 判断包含不支持的枚举或互相矛盾的业务组合
- **THEN** 系统拒绝将其升级为有效直接候选原因，并按既有答案校验链路处理

### Requirement: 历史判断保守兼容
读取缺少业务类型或相关性的历史答案时，系统 SHALL 将其归为未知并保持原顺序与原文，不得自动分类为直接候选原因。

#### Scenario: 打开旧版本 Run
- **WHEN** 历史判断只有正文、引用和确定性
- **THEN** 工作区与报告将其放入其他或未知判断，所有原文和引用仍可查看

### Requirement: 首屏短结论与下一步
完成结果的首屏 SHALL 优先展示由真实结果字段形成的短结论及最多三项下一步。系统 MUST NOT 截取长摘要冒充新摘要，也不得虚构概率、优先级或已执行检查。

#### Scenario: 候选原因答案完成
- **WHEN** 用户查看包含直接候选原因、建议、风险和数据性质的完成 Run
- **THEN** 首屏明确其为候选分析而非确诊，并展示实际直接候选数量及按原顺序取得的最多三项建议

#### Scenario: 建议超过三项
- **WHEN** 本轮建议超过三项
- **THEN** 首屏展示前三项并提供查看全部内容的入口，其余原文不丢失

### Requirement: 判断分组与默认焦点
工作区 SHALL 分开呈现直接候选原因、背景观测或上下文、其他或未知判断。默认焦点 MUST 优先来自直接候选原因，不得默认选中无关观测。

#### Scenario: 首项为背景观测
- **WHEN** 原结果首项是背景观测而后续存在直接候选原因
- **THEN** 默认焦点落在第一条直接候选原因，背景观测仍在其他分组保留

#### Scenario: 没有直接候选原因
- **WHEN** 完成结果没有直接候选原因
- **THEN** 工作区展示轮级摘要和实际分组，不自动选中其他或未知判断冒充候选原因

### Requirement: 完整结果与直接证据
工作区 SHALL 保留完整摘要、全部判断、建议、不确定点和限制的访问入口，并优先展示当前焦点的直接引用。其他登记来源 MUST 按需查看且保留数据性质。

#### Scenario: 查看当前判断证据
- **WHEN** 用户切换直接候选原因
- **THEN** 页面更新该判断及直接引用但不提交新调查，其他来源不会冒充该判断依据

#### Scenario: 展开完整结果
- **WHEN** 用户选择查看完整结果
- **THEN** 页面可读取未截断摘要及全部轮级内容，不重复发起模型调用

### Requirement: 移动端结果阅读顺序
窄屏结果页 SHALL 按结论、下一步、候选原因、当前判断与证据的顺序提供内容，不得要求用户先滚过全部判断列表才能看到当前结论。

#### Scenario: 手机查看完成 Run
- **WHEN** 用户在窄屏打开包含多个判断的完成 Run
- **THEN** 首屏优先可读到短结论和下一步，并能通过分组控件进入候选原因及证据
