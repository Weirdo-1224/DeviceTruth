# Proposal

## Why

专业工作台已有逐轮调查能力，但用户仍可能在待答时看不到问题、在失败或窄屏时打不开证据，或在查看历史时把当前输入的资产误当成旧轮资产。V0.3 R0-A 将工作台聚焦于当前调查要点，并修复提问、来源和运行状态之间的交互断点。

## What Changes

- 任务区同时标明查看轮与会话活动轮。调查导航显示简短预览和类别，中央显示当前焦点，完整结果按需打开，风险和安全限制默认可见。
- 专业端以原型图作为视觉验收参考，采用浅色紫蓝主题、顶部任务卡和白色圆角主面板。桌面左侧常驻「近期调查」，窄屏从顶部入口按需展开。
- F01 让待答正文独立于消息记录的展开状态。刷新或浏览历史时仍可定位待答轮，继续使用 `replyTo` 三元组恢复同一 Run。
- F02 为已完成、失败和取消轮提供统一的已登记来源入口和按需抽屉。窄屏保留入口，抽屉支持键盘关闭和焦点返回，读取失败有明确状态。
- F04 由 SSE 通知触发响应式更新与持久状态回读，继续使用现有历史事件、seq 去重、断线续传和有界轮询。等待补答与业务终态分别处理。
- F08 让历史资产、`asOf`、引用与操作目标分别跟随实际 Run。保留显式深入调查和自由输入的既有提交能力。

范围限定在专业页及其回归验证。R0-B 负责 F03 幂等回执、服务端未决 Run 约束、跨轮引用复制和时点继承。模型提示词、第二次 LLM 总结、Agent Core 协议、数据库、普通模式、管理端、Canvas、动态图谱、新 Agent 框架、全面路由或全局状态迁移均在范围之外。

## Capabilities

### New Capabilities

主规格目录目前没有已归档能力。以下三项沿用旧 Change 的能力路径，为各自新增可独立验证的要求。

- `professional-diagnosis` — 单焦点布局、结果语义与终态证据可达性。
- `investigation-recovery` — 响应式状态同步以及查看轮与活动轮的上下文绑定。
- `investigation-continuation` — 待答正文的持续可见性与同轮补答定位。

### Modified Capabilities

当前没有已归档规格需要改写。

## Impact

复用 Vue 专业页、会话与 Run 读取、既有引用授权接口、SSE 和轮询。预计改动位于 `frontend/src/` 和既有验证脚本。服务端 API、数据库结构与发布配置沿用现有合同。
