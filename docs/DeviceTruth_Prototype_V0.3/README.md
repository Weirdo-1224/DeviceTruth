# DeviceTruth · V0.3 产品设计原型

> 设计演示，不是已连接后端的正式系统。基于用户提供的 `prototypes.zip` 中 V0.2 HTML 原型与三端截图，进行保留功能定位的改进。

## 如何打开

直接用浏览器打开 `index.html`，默认进入**专业用户端**。顶部深色 `DESIGN REFERENCE V0.3` 是**设计稿预览工具栏**，不属于生产应用导航。可通过右侧三个选项切换普通用户、专业用户、平台管理；支持 URL `#consumer`、`#pro`、`#admin`。

也可以直接打开 `preview-standalone.html`：CSS 和 JS 已内嵌，方便单文件预览。无需依赖外部网络、CDN、字体或前端构建工具。HTML、CSS、JS 均可编辑。

## 交付内容

- `index.html`：三端页面 DOM 与统一 SVG 图标。
- `assets/styles.css`：设计 Token、卡片、导航、工作区、响应式样式。
- `assets/app.js`：**纯本地**交互演示，未连接任何 API，也不会保存资料。
- `screenshots/`：真实 Chromium 运行截图，含三个桌面端，以及专业端平板与手机布局。
- `DESIGN_REVIEW.md`：V0.2 问题与 V0.3 改进范围。
- `CODEX_HANDOFF.md`：交给 Codex 的严格实施提示词与验收规范。
- `reference/`：原始 V0.2 HTML 和截图，用于差异对照（保持未修改）。
- `test_visuals.py`：可选的 Playwright 渲染和交互检查（需要 Python playwright 与 Chromium）。

## 三端设计约束

| 端 | 核心用户任务 | V0.3 最重要的变化 |
|---|---|---|
| 普通用户 | 自然语言描述异常，按追问继续对话 | 将会话、追问选项和底部统一输入区域组织为连续对话；右侧保留判断与安全提醒 |
| 专业用户 | 浏览焦点、核对证据、补充现场观察、继续调查 | 增加证据来源性质、差异对照、持续输入、Run 时间线，以及焦点与内容联动 |
| 管理端 | 了解平台运行与规划管理能力 | 示例 KPI 显式标注，管理菜单提供说明页面，不暗示缺失的后台操作已完成 |

## 可点击的演示交互

1. 专业用户：三个调查焦点切换后，**标题 / 摘要 / 状态 / 对照事实 / 核验建议 / 输入提示**同步变化。
2. 专业用户：切换「深入调查 / 补充现场观察」，输入文字提交后呈现**本地演示记录**；不会发起真实 Run。
3. 专业用户：附件仅显示本地文件名，**不会上传**。证据卡打开来源属性和限制说明；Run 过程可折叠。
4. 普通用户：追问选项填入输入框，用户确认发送后更新示例对话，不生成虚构 AI 回答。
5. 管理端：选择各管理模块显示待建设功能边界，不虚构增删改查能力。
6. 所有示例数据、模拟状态和不可用功能均明确标记，正式接入前不能将其称为“已实现”。

## 已验证

- Chromium 无脚本异常；桌面端三个模式可渲染。
- 关键点击路径：焦点联动、调查模式切换、示例提交、证据弹窗、普通端追问、管理端菜单。
- 390px 专业端无页面横向溢出。移动端属于**适配示例**，需要正式项目再确认移动端优先级。
- **没有**与实际 DeviceTruth 仓库联调。接口名称和已有能力需由 Codex 阅读真实源码确认。

## 对正式开发的重要提醒

**不要把这份原型当成后端业务规格。** 它定义用户可见的信息结构、视觉样式和交互状态。真实的业务实体（Conversation、Run、Reference、Asset、Observation、Skill 等）、鉴权和异常状态必须尊重现有仓库。`CODEX_HANDOFF.md` 中有明确处理规则。
