# Spec Delta

## Purpose

让用户能够辨认、搜索和找回真实调查任务，并及时发现待补答或进行中的会话，同时避免空草稿和无归属数据污染历史列表。

## ADDED Requirements

### Requirement: 会话摘要完整表达任务
会话发现列表 SHALL 为每个非空会话提供目标标题、最近排查设备、最新状态、活动与待答数量、Run 数和更新时间。标题 MUST 来自真实首条用户目标的安全截断，不调用模型生成。

#### Scenario: 查看已有调查
- **WHEN** 用户打开包含多个会话的历史列表
- **THEN** 每项直接展示可辨认的目标摘要、设备和状态，而不是通用会话名称

#### Scenario: 切换其他会话后查看状态
- **WHEN** 非当前会话存在待补答或进行中的 Run
- **THEN** 历史列表仍显示该会话的真实待答或活动状态

### Requirement: 会话状态优先与筛选
会话发现 SHALL 优先突出待补答任务，并支持按关键词、设备和状态筛选。状态筛选 MUST 使用服务端持久 Run，而非当前浏览器已加载数据。

#### Scenario: 筛选待补答会话
- **WHEN** 用户选择待补答筛选
- **THEN** 列表只返回当前身份下存在待答问题的会话

#### Scenario: 搜索设备或目标
- **WHEN** 用户输入设备标识或目标关键词
- **THEN** 列表返回匹配该条件的会话，清空条件后可恢复完整分页列表

### Requirement: 有界稳定分页与归属保护
会话摘要查询 SHALL 使用有界游标分页和稳定排序，所有目标、Run 聚合与筛选 MUST 受服务器确定的身份范围限制。系统 MUST NOT 通过逐会话详情请求拼装列表。

#### Scenario: 加载下一页
- **WHEN** 第一页存在后续游标且用户加载更多
- **THEN** 系统按相同筛选条件返回后续项目，不重复或遗漏稳定排序边界上的会话

#### Scenario: 跨身份数据隔离
- **WHEN** 另一 owner 或 project 存在匹配搜索条件的会话
- **THEN** 这些会话及其目标、设备和 Run 状态均不出现在结果中

### Requirement: 新调查草稿延迟落库
新调查 SHALL 先作为本地草稿存在，首次提交调查时才创建服务端会话。重复点击、创建后发送失败及草稿附件 MUST NOT 造成重复消息或丢失用户输入。

#### Scenario: 新建后未提交
- **WHEN** 用户点击新调查但尚未提交第一条消息
- **THEN** 历史列表不会出现新的空会话，已有调查保持可访问

#### Scenario: 创建会话后首次发送失败
- **WHEN** 服务端会话已创建但首次消息提交失败
- **THEN** 页面保留当前会话、草稿及待随附附件状态，用户可重试且不重复创建会话

### Requirement: 空历史与旧接口兼容
会话发现 SHALL 隐藏没有 Run 的空会话但不物理删除其审计数据，既有会话列表接口 SHALL 保持可用。

#### Scenario: 已存在空会话
- **WHEN** 查询包含历史遗留空会话的摘要列表
- **THEN** 空会话不占用列表位置，有实际消息和 Run 的会话仍按正常规则返回
