# Spec Delta

## Purpose

区分本次排查使用的附件和可供同空间其他调查复用的知识，避免某台设备的临时记录因为上传即入库而污染其他调查。资料原文、版本、原作者和数据性质应贯穿上传、检索、发布和引用回读。

## ADDED Requirements

### Requirement: 调查上传默认绑定调查
从调查入口上传的资料 SHALL 绑定当前调查、空间及上传者，默认只作为该调查附件，不自动发布到空间知识库，也不发起模型分析。上传、读取原文、重试导入均必须校验当前成员权限；只读成员不能上传。

#### Scenario: 上传临时检查记录
- **WHEN** 协作成员向调查 A 上传支持的检查记录
- **THEN** A 的参与者可以查看该附件，调查 B 不因同属一个团队就在检索中获得该附件；上传本身不创建 Run

#### Scenario: 跨空间文件或导入重试
- **WHEN** 请求使用其他空间的 fileId、documentId，或无权限时重试导入
- **THEN** 拒绝访问，不读取原文或调用 embedding，也不通过错误信息泄露路径和正文

### Requirement: 显式知识发布
管理员和协作成员 SHALL 能将当前空间的调查附件明确加入该空间知识库，并确认资料名称及适用设备/条件。发布必须保留原始附件和原作者，不迁移或改变其历史归属；只读成员不能发布。重复发布 SHALL 不产生重复知识条目。

#### Scenario: 发布有复用价值的资料
- **WHEN** 用户在附件详情确认名称、适用范围及目标空间并提交发布
- **THEN** 同空间其他调查可以检索已成功发布的版本，显示发布人、原作者、原文版本和来源性质，原调查附件仍可回读

#### Scenario: 发布失败或重复点击
- **WHEN** 发布解析/索引失败，或同一版本被重复提交
- **THEN** 失败不显示为已可检索，原附件不丢失；重试可恢复，重复提交不产生重复知识

### Requirement: 检索和原文读取作用域一致
工具检索 SHALL 仅召回当前空间已发布知识及本执行段已确认的本调查附件版本。未引用的讨论、其他调查未发布附件、个人或其他团队资料均不可召回；原文工具和引用登记不得绕过此范围。人员可按空间权限主动阅读其他团队调查，但这不扩大当前 Run 的材料范围。

#### Scenario: 两项调查的附件隔离
- **WHEN** A、B 属于同一团队，A 的附件未发布，B 的 Run 调用知识检索或原文工具请求该片段
- **THEN** B 的 Run 无法检索或取得该附件片段；发布成功后才可按资料版本及适用范围访问

#### Scenario: 运行期间新增附件
- **WHEN** 当前 Run 已接受正式输入，另一成员又向调查上传附件
- **THEN** 新附件可以在界面阅读，但不进入正在执行的输入材料集合；在下一次明确补充或补答确认时才纳入执行段

### Requirement: 发布不提升来源可信度
上传、解析、索引、发布或引用讨论 SHALL NOT 自动把用户描述、历史记录或 SIMULATED 数据变成现场实测或已确认配置。答案引用只允许使用本 Run 真正取得并登记的引用 ID，直接依据与其他登记来源必须区分。

#### Scenario: 发布模拟记录
- **WHEN** 一份 SIMULATED 或未核实检查记录被加入团队知识库并被新调查检索
- **THEN** 摘录、引用和报告仍显示原数据性质，不以发布行为证明故障或现场配置

### Requirement: 资料格式及原合同兼容
系统 SHALL 保留现有 MD/TXT 支持与有界异步解析/失败重试；PDF/OCR 尚未实现的状态必须如实展示。现有显式知识导入入口仍按知识导入使用，不能因新增调查附件而静默改变既有调用含义；新调查上传必须采用明确的调查作用域。

#### Scenario: 从旧知识导入入口上传
- **WHEN** 已授权调用方继续使用原显式知识导入接口
- **THEN** 仍按其原有知识导入用途处理；新附件入口与其区别明确，旧调用方不被额外要求提供调查 ID

#### Scenario: 不支持的格式
- **WHEN** 用户尝试上传 PDF 或不支持的格式
- **THEN** 如实展示现有拒绝或待解析状态，不伪造正文、页码、可检索状态或引用
