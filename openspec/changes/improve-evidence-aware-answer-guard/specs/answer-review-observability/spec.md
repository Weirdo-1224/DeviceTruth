# Spec Delta

## Purpose

让维护者和用户能够理解答案哪些部分被支持、修正或暂缓，并在不暴露凭据、私有提示词或未授权草稿的前提下复现处理依据。验收需同时检查有用回答与安全反例，不再以运行完成或模型连通代替答案质量。

## ADDED Requirements

### Requirement: 复核结果可定位且脱敏
系统 SHALL 记录问题类型、目标陈述/指导项、原文定位、可选支持来源或缺失前提及最终处置。普通事件和报告 MUST 使用授权白名单投影，不直接保存或回显完整模型输入/草稿作为公开诊断信息。

#### Scenario: 再次出现拒绝
- **WHEN** 答案因语义问题被修正或拒绝
- **THEN** 可判断触发项属于资料事实、设备结论、引用或执行前提，不只获得全局原因码

#### Scenario: 普通成员查看审计
- **WHEN** 授权成员或团队外账号请求复核详情
- **THEN** 前者仅见可授权的最小证据，后者不能获得内容、来源或草稿；日志不包含凭据或原始 Prompt

### Requirement: 有界复核和修正遵守运行生命周期
系统 MUST 将语义复核和修正纳入现有总时间、调用/步数预算及取消和撤权检查。超时或复核失败时保留已验证内容，争议项待确认；不得无界重试或绕过硬约束。

#### Scenario: 复核期间撤权或取消
- **WHEN** 语义复核或修正等待期间发生取消或执行权限撤销
- **THEN** 不采纳迟到输出、不发起后续调用，沿原 Run 生命周期持久收口

#### Scenario: 复核预算耗尽
- **WHEN** 达到有界调用或时间上限而争议仍未解决
- **THEN** 输出明确的局部有限状态，或不能拆分时整份有限结果，不伪装成完整成功

### Requirement: 新旧结果和报告可兼容回读
系统 SHALL 为新复核合同显式标记版本，保留存量结果、旧构造及原输入用法。缺少新字段的历史结果不得被推断为已完成新语义核验，报告不得为了展示复核状态再次调用模型。

#### Scenario: 回读旧结果
- **WHEN** 打开没有新复核字段的历史 Run
- **THEN** 保留原内容与语义，并显示旧合同或未知复核状态，不追溯改写为新标准通过

### Requirement: 正反例和真实模型共同决定验收
系统 SHALL 在相同证据输入下分别检验资料事实、历史/当前设备、用户记录、局部依赖与规程条件。真实模型验收 MUST 分开记录链路通过、答案可用性、有限结果、实际引用和模型尝试；不得为通过删除反例或放宽来源权限。

#### Scenario: 资料问答回归
- **WHEN** 无现场资产但有适用模拟知识资料的解释任务完成
- **THEN** 检查正常知识内容及引用是否保留，不以 HUMAN_REVIEW 加 COMPLETED 或仅一次通过宣称问题已解决

#### Scenario: 相近反例
- **WHEN** 相同上下文改为无依据当前故障、缺规程步骤或遗漏关键前提
- **THEN** 问题内容不被放行，其他独立有效内容仍按合同保留

### Requirement: 新版复核调用上限
系统 MUST 对新版交付执行一次整体语义复核及至多一次定向修正，修正后只做程序硬校验。历史v1检查点恢复保留原预算，不迁移为未审核通过。

#### Scenario: 新版回答存在局部问题
- **WHEN** 整体复核返回实质问题
- **THEN** 最多一次修正，不启动第二次模型复核；修正失败时有限收口，不能直接展示问题草稿
