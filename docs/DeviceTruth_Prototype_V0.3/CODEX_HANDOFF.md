# 给 Codex 的实施提示词（可直接复制）

你正在维护 **DeviceTruth** 的真实 Vue 前端。现在提供 `DeviceTruth_Prototype_V0.3/`，这是从 V0.2 原型审查后迭代的**三端 UI 基准**，其中的 `index.html`、`assets/styles.css`、`assets/app.js` 和 `screenshots/` 用于视觉与交互参考。

## 任务目标

把现有前端调整为 V0.3 的结构和视觉，**优先实现专业用户的诊断工作台**，再统一普通用户与管理端的视觉语言。不得丢失现有 Agent 运行、历史调查、资料引用、文件上传等已有功能。按当前后端真实能力逐项映射，不得把演示逻辑和演示数据当成真实逻辑。

## 强制执行的阶段与限制

### 阶段 A：审查与映射（本阶段只输出文档，不改代码）

1. 阅读 `README.md`、`DESIGN_REVIEW.md`、`index.html`、`assets/styles.css`、`assets/app.js`，以及 `screenshots/pro-desktop.png`、`screenshots/consumer-desktop.png`、`screenshots/admin-desktop.png`。
2. 彻底检查当前 Vue 工程的页面入口、路由、组件树、样式文件、状态管理、API client、Agent SSE/Run/Reference/Asset/Skill 相关数据流。
3. 制作一张 `设计元素 → 当前业务组件 → API / 状态模型 → 适配方式 → 风险` 的完整映射表。
4. 特别核实：当前项目有没有真实认证/RBAC、多轮补问、调查任务独立运行、附件上传、报告导出、用量统计、设备配置时点有效性、来源可信状态。**不能仅凭 V0.2 原型描述就认定这些 API 已实现**。
5. 把与现有功能冲突的设计标记为 `待决策`，不能悄悄删掉业务功能，也不能让模型自创页面结构。
6. 输出 `docs/design/UI_V03_IMPLEMENTATION_PLAN.md`，包含文件级改动清单、适配方案、验收用例和风险清单。未经确认不要开展大规模改动。

### 阶段 B：实现（以确认后的方案为准）

**视觉基准**
- V0.3 的三张桌面截图是主要视觉目标；HTML/CSS 定义布局结构、间距、色板、输入组件和状态样式。还原目标不是简单“相似的紫色风格”，而是页面区域的比例、位置、层次和交互结构。
- 原型顶部深色 `DESIGN REFERENCE V0.3` 预览切换条仅用于展示**三种用户端**，不应复制进生产 UI；正式系统使用已有路由和角色能力。
- 保留页面品牌与现有业务数据；原型的 PLC/新能源车及 KPI 文案只用于占位，绝不硬编码为用户实际业务事实。
- 不能自行把专业页重新改为 `历史会话 | 资料断言 | 大段报告` 三栏结构。目标为 `调查方向 | 当前焦点+统一输入区 | 证据上下文`，完整原始报告通过既有历史或可展开区域保留。
- 正式页面不可出现浏览器原生文件控件外观。要用统一的附件按钮，保留可访问的 file input 实体。

**功能基准**
- 普通端：用户问题 → 真实 Agent 回复/追问 → 选择当前待补问题的答案 → 继续同一会话/适当的 Run。原型的追问内容不能替换真实 pendingQuestion。
- 专业端：切换调查焦点**只是切换 UI 视图**；不会自动创建新的 Run。真实证据、结论、工具轨迹与历史 Run 由服务端读取，并各自绑定来源、时间和授权。
- 专业端：“深入调查”与“补充现场观察”应有明确业务区别。前者发起/继续调查请求；后者提交未核实观察。不能把人工输入直接写入 `CONFIRMED` / 权威事实表。
- 专业端：必须有进度/运行中/空结果/错误/重试/中断反馈；完整报告和证据引用不能因视觉重构而丢失。
- 管理端：严格按照后端 RBAC 实现可见性和操作权限。没有后端接口的模块显示明确未接入状态，不得假实现 CRUD 或显示虚假 KPI。
- 后端所有路径及数据模型以源码为准。V0.2 注释中提及的 R5/R8/R11/R12 等仅为旧原型描述，不能当作已验证的接口名称。

**设计实现**
- 建立共享 Design Tokens、基础按钮/标签/卡片/输入组件，尽量使用已有 Vue 架构，无需为了美观引入新框架。
- 统一正常、hover、focus、disabled、loading、empty、error 状态。
- 限定品牌主色使用范围，避免整页浅紫色背景与多层嵌套卡片。
- 保持桌面布局；在宽度 ≤1360px 时证据侧栏可以下移。明确处理 1366×768、1600×1000 和窄屏布局。
- 保留完整的键盘输入、Enter/Shift+Enter 行为、附件校验、对话滚动与长文本断行。原型中仅有演示，不代表完整生产实现。

### 阶段 C：截图与验收（必须完成）

1. 本地运行现有 Vue 前端，使用可重复的样例数据/Mock 测试场景。
2. 在 **1600×1000** 截图对照 `screenshots/pro-desktop.png`，并分别检查普通端和管理端；在 1366×768 和 390×844 检查响应式布局。
3. 把真实浏览器截图保存到仓库可审查目录，不能只提交代码或 AI 文字“已完成”。
4. 按区域列出差异：侧栏宽度、主体栏宽、标题/标签层级、卡片对齐、证据布局、输入区、内容折行、状态色。
5. 发现结构性差异必须先修复再验收；没有获得浏览器截图时，明确标记“视觉尚未验证”。
6. 跑已有的构建、关键页面交互、Run/SSE 和资料来源的回归测试。不能以构建成功代替视觉或功能验收。
7. 交付改动文件清单、三端截图、未解决差异和真实功能验证结果。

## 禁止行为

- 禁止仅凭截图重新生成一套与原型不一致的“类似界面”。
- 禁止为了把页面塞进原型而删除真实 Run、证据、上传、追问或报告功能。
- 禁止为演示添加未经授权的后端接口或绕过权限。
- 禁止混淆 `SIMULATED / UNCONFIRMED / DOCUMENTED / VERIFIED` 等事实与来源语义。
- 禁止用示例 KPI、演示时间与记录代替真实系统值。
- 禁止未截图验收就宣布 UI 已达到设计目标。

**先执行阶段 A 并交付映射及实施方案；得到审核意见后再实施阶段 B/C。**
