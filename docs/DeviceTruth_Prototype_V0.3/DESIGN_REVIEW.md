# DeviceTruth 三端 V0.2 → V0.3 设计评审

## 审查依据

用户上传的 `prototypes.zip`，其中包含 `index.html` 和普通用户、专业用户、平台管理三张截图。本文的“旧版问题”来自该原型及其 HTML 交互逻辑，**不是**对现有 Vue 生产项目的源代码审计。

## 总体结论

V0.2 最值得保留的是：三类用户定位、专业端“调查焦点”的信息架构、管理端能力边界和示例数据提示。问题不在简单的配色，而在交互闭环、来源语义以及多页面统一性。V0.3 改进应优先让业务模型可读、可操作，再进行视觉收敛。

## P0：业务展示与交互一致性

| 旧版问题 | 依据 | V0.3 处理 |
|---|---|---|
| 专业端选中焦点只改变标题和摘要 | V0.2 `selectFocus` 只改 `focusTitle`、`focusBrief` | 联动对照事实、状态、后续核验步骤与输入提示；不把焦点选择等同于发起新 Run |
| 缺乏持续多轮输入的清晰入口 | V0.2 专业端只有“深入调查/补充现场信息”两个动作入口 | 新增统一输入区，显式选择调查或现场观察，发送前需有内容 |
| 不区分证据来源与现场事实的可信状态 | V0.2 证据是两张通用资料卡 | 用“用户口述/文档记载/未现场确认”做语义区分；细节弹窗显示来源性质和限制 |
| 普通端追问只是修改样式并弹提示 | V0.2 `chooseChip` 不提交信息 | 先填入输入框，允许修改，确认发送后只更新演示状态，不伪造模型回答 |
| 管理端导航仅更换标题，正文仍是总览 | V0.2 `adminNav` 修改 `admin-title` | 未实现模块显示有边界的规划说明，避免混淆“可点击”与“有后台能力” |

## P1：视觉与布局

| 旧版问题 | V0.3 处理 |
|---|---|
| 普通端大尺寸插画抢占首屏 | 改成紧凑 hero，突出会话与下一步操作 |
| 专业端大块结果卡不够结构化 | 采用“调查方向 / 焦点证据对照及输入 / 来源与 Run 上下文”三栏桌面布局 |
| 大量浅紫容器层层嵌套 | 紫色限定为主操作、当前选中、少量重要反馈；中性灰白为主要画布 |
| 卡片阴影、标签、按钮风格不同 | 统一设计 Token、边框、圆角、按钮与 SVG 图标 |
| 专业端底部操作碎片化 | 将两个动作规范为输入模式，使用同一个文本框和发送入口 |

## P1：专业端的信息模型（最关键）

布局必须表达下列区别：

1. **输入线索**：用户口述、历史资料与模拟观察，性质不同。
2. **资料性陈述**：配置记录记载 D-120B，并非“当前现场必定为 D-120B”。
3. **冲突/缺口**：模型可识别冲突，但不能据此确定真实现物。
4. **核验建议**：人工现场操作由合格人员执行；步骤不应由 AI 虚构成已完成。
5. **调查状态**：阶段结果已生成、现场核验未完成，必须可同时显示。
6. **历史独立性**：不同 Run 关联各自证据和时间线，不强行合并为单一确证状态。

### 设计流程（与真实 API 分离）

任务概览 → 选择一个调查方向 → 观察证据差异 → 查看来源和有效性 → 选择继续调查或补充观察 → 提交后创建/继续受控 Run → 查看时间线与报告。

当前 V0.3 只模拟该流程的前端交互。实际运行边界由项目已有代码和接口决定。

## P1：管理端缺口

V0.3 仅展示管理导航和规划状态，**没有实现**：真实的用户 CRUD、RBAC、配额和用量聚合、审计日志写入、知识版本发布/撤回、Skill 启停等。任何真实后台能力都需在服务端落实访问控制。对实际不可用的指标，正式页面应使用“暂无数据 / 未接入”，而不是把示例 KPI 计入业务事实。

## P2：后续设计，不属于本次 V0.3

- 完整多轮长对话和较复杂的 agent streaming 中间状态；
- 大量证据来源的过滤、分组、版本回溯及证据图；
- 管理端正式的每个 CRUD 页面和管理审批流；
- 完整可访问性审计、真实移动端全流程；
- 离线保存与云端同步；
- 定量视觉回归、设计系统组件库抽离。

这些应在正式前端与后端能力核对后分批实施，避免为一次视觉重构引入过量新业务范围。

## 统一视觉规范（V0.3）

- **总体方向**：简洁现代的工业 AI 工作台；可信度和证据清晰度优先于装饰。
- **主题**：浅色中性背景 `#F7F9FC`；白色卡片 `#FFFFFF`；文本 `#1C2740`。
- **主色**：`#6757DD`；只用于主要动作、当前导航、焦点与选中态。
- **语义色**：绿 `#14866E`（有效完成/成功）、橙 `#AC6824`（待核验/缺口）、蓝 `#3974B5`（资料与信息）、红 `#B85458`（风险/失败）；颜色不能是唯一信息载体。
- **边框**：`#E3E9F2`；统一 10–14px 容器圆角，轻微阴影。
- **文字层级**：主标题 22px；卡片标题 12–20px；正文 12–13px；元信息 10–11px。正式开发可提高最低字体以满足可读性。
- **侧栏**：222px；工作区层级优先于装饰导航。
- **专业端桌面布局**：216px 调查方向 + 自适应中心工作区 + 236px 证据上下文；窄屏下证据区移至下方。
- **统一图标**：内嵌 SVG，不依赖 emoji、外部图标 CDN 或操作系统字体。

## 设计验收检查

- 三端布局、主要栏宽、导航、卡片顺序与 V0.3 截图一致；顶部深色预览切换条**不进入正式产品**。
- 专业端焦点切换时，状态、证据和步骤必须同步刷新。
- 不得把 `UNCONFIRMED` / `SIMULATED` 的用户观察或演示资料在 UI 上表现为确证事实。
- 普通端选项必须与当前追问关联，不使用硬编码答案覆盖真实后端数据。
- 管理 KPI 必须区分真实数据、未采集值和原型示例。
- 无原生 `<input type="file">` 视觉暴露；附件选择需保留清晰的状态和失败反馈。
- 对无权限、加载中、空数据、模型异常、长文本、错误附件和长时间运行状态有明确处理。
