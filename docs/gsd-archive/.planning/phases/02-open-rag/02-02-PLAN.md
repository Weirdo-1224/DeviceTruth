**具体步骤**

<action>

1. ASK_USER 原子保存问题、pendingQuestionId/questionVersion、runId、原始消息、必要工具结果/引用与累计步数，状态 WAITING_FOR_USER 后释放 worker。
2. 补答 API 显式带 runId/pendingQuestionId/questionVersion：校验归属/等待状态/问题匹配，在单进程正常路径串行消费，回复+状态同事务写入，WAITING→QUEUED→RUNNING。
3. 从 PG 读取原始消息、必要引用和问题重建新一轮上下文，沿同一 run 检索/回答，可再次追问。
4. 错 run、错题号、旧问题或终态回复拒绝且不新建 run。
5. 引用读取仍鉴权。
6. 此处只交付基本状态前置条件和同进程关联，M2 再补跨 worker CAS/租约、重复请求幂等与崩溃恢复。
7. 答案 DTO 区分事实/可能性/建议/人工项。
8. 校验本 run 引用及风险，模型技术失败为 FAILED。

</action>
