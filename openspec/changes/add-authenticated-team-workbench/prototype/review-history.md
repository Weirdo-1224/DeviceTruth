# DeviceTruth 登录与团队协作原型

日期：2026-11-19（Asia/Shanghai）

## 本轮交付

`team-investigation-prototype.html` 是对话内可交互原型。沿用专业检修、调查驱动、电脑优先和浅色工程工具风格，包含：

- 邮箱密码登录、注册、找回密码、重置密码、受邀加入。
- 个人空间和团队空间切换，新账号不继承演示账号的私人调查或团队资格。
- 创建团队、邀请成员、角色调整、只读状态、团队名称设置。
- 团队共同调查、带作者的讨论、明确引用讨论到正式补充。
- 一项调查只有一轮未结束分析；运行时可准备草稿，结束后不自动提交。
- 等待补充时提交补答，继续同一轮；取消运行需确认，保留既有记录且后续轮号不复用。
- 调查附件、本地 MD/TXT 阅读、明确发布到当前空间知识库、保留原作者和来源性质。
- 资料与证据侧栏、设备档案、正式分析记录、调查过程、报告阅读。

原型独立于仓库产品代码；本轮没有开发或接入真实认证、团队权限、数据库、邮件、embedding 或模型服务。

## 已确认的产品选择

用户逐项确定：一线维修人员/工程师；调查工作台；电脑优先；无可靠结论时优先继续调查；克制工程风格；前端主链路重整。

新增功能确定：多人接续同一调查；个人与团队双空间；邮箱密码自主注册；协作成员可以继续他人调查；讨论与模型输入分开；同项调查串行分析；附件不自动进入共享知识库。

用户随后明确授权“制作”，当前目标是验收原型，之后再规划并开发后端。

## 怎样体验

1. 默认进入华东检修组的空调调查。打开团队讨论，引用老李的讨论到补充区；确认提交后进入运行状态。
2. 在运行期间填写新草稿，再点击顶部的“结束本轮演示”。草稿仍在，不自动发起下一轮。
3. 顶部“预览场景”可进入只读成员、协作成员、同事正在分析、等待补充、登录注册和接受邀请等状态。
4. 调查附件 → 加入知识库 → 填写适用范围 → 确认；再从左侧知识库查阅，保留原作者。
5. 登录场景 → 注册 → 进入独立个人空间 → 创建团队 → 邀请成员 → 预览受邀加入流程。

顶部预览场景与“结束本轮演示”是评审控件，不是产品功能。

## 原型中的具体默认策略

- 管理员、协作成员、只读成员三种角色；团队空间的调查面向本团队可见。
- 管理员和协作成员可明确发布附件到当前空间知识库；只读成员不能发布。
- 发起人和团队管理员可取消本轮，取消前确认；其他协作成员不能取消同事的分析。
- 个人/团队间没有自动迁移、自动共享，也没有并行调查分支。
- 真实账号与邮件身份不在此原型中验证。密码仅用于本地表单体验，不写入原型状态或 widgetState。

以上交互应随原型一起核对；后端契约仍需在原型确认后制定。

## 关键实现及运行链路

`state` 保存当前演示身份、工作空间、页面和查看轮次；`cases` 保存演示调查；`libraries` 按空间/个人身份区分资料；`scopeCases()`、`members()` 和 `library()` 决定当前页面能显示哪组演示内容。

`render()` 根据当前页面选择登录表单或工作台外壳。`caseView()` 组织判断、讨论、分析记录和调查过程；`drawer()` 在不离开调查的情况下展示来源、附件、报告及发布确认。

输入只写入当前用户的草稿。发表讨论只追加讨论；引用动作保留原文、作者和时间；明确提交才追加正式分析记录并进入一轮运行演示。`finishRun()` 结束演示但不生成真实诊断，也不自动提交后续草稿。补答继续原轮，取消保留记录。

所有内容在当前页面内模拟。页面选择等少量枚举可通过宿主 widgetState 恢复；账号、密码、文件正文、讨论和调查数据不依赖持久存储，刷新可清空。用户输入均作为文本转义展示。

### 失败及修复历史

1. 首次主检查执行到第 3 项时，2 通过、1 失败：讨论未追加。定位为预览 iframe 的沙箱不允许原生表单提交。改为在本地取消默认提交，再分发本地 submit 事件；同时补充 Enter 键路径。随后原 40 项检查全部通过。
2. 增加补答和取消检查后，执行到第 26 项时，25 通过、1 失败：测试从关闭的 details 使用 inner_text 读取取消原因码。记录实际存在；测试改为先展开技术详情再核对，不更改产品语义。随后 47 项主检查通过。
3. 视觉检查发现等待补充在侧栏误写“正在分析”，以及自建团队调查标题曾用固定示例头像；分别改为按等待状态和实际空间成员渲染，两个补充断言通过。

## 尚未验证的真实能力

此轮验证只证明原型交互、示意角色反馈和本地数据分组。真实账号认证、服务端授权隔离、邮件送达、数据库持久化、模型调用、向量检索及多浏览器实际并发，均留待后端开发后验收。原型中的权限按钮不代替服务端授权。
