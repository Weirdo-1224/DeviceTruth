# Spec Delta

## Purpose

让专业工作台在用户浏览历史、网络中断及服务端推进状态时，持续展示正确轮次与操作目标。界面以持久化记录判断状态，并让历史资产、业务时点、来源和时间线保持在所属轮次。

## ADDED Requirements

### Requirement: 查看轮与活动轮分别定位

工作台 SHALL 独立标明当前查看轮及会话非终态轮的真实状态，并提供回到活动轮的入口。查看轮的资产、业务时点、引用及时间线 SHALL 来自该轮。切轮时旧内容立即退出可见区，迟到响应不得覆盖新视图。

#### Scenario: 历史资产与输入资产不同
- **WHEN** 当前查看轮为资产 A 和业务时点 T1，当前活动轮使用资产 B 且底部输入已选择资产 C
- **THEN** 历史标题与设备快照仍使用 A/T1 并展示该轮引用，活动轮单独展示，C 仅用于后续普通提交

#### Scenario: 快速切轮及晚到响应
- **WHEN** 用户在同一资产的两个不同时点的 Run 之间切换，或切换会话后旧引用、资产快照、Skill 或历史事件才返回
- **THEN** 目标轮立即显示自己的内容或加载态，旧抽屉退出，旧响应不出现在目标轮，也不在切回同一 ID 时覆盖较新读取

#### Scenario: 刷新时保留所看历史
- **WHEN** 用户固定查看历史轮，同时活动轮推进且触发刷新
- **THEN** 历史选择仍在，活动状态单独更新，用户可返回活动轮；重新载入页面时用服务器数据恢复会话和待答入口

### Requirement: 操作由所选目标和持久状态决定

工作台 SHALL 将取消、补答、深入调查和自由输入绑定到各自真实 Run/会话目标，并令按钮、键盘和处理函数使用一致许可条件。尚有活动轮时仅允许适用的已有轮操作。深入调查只可由已完成的查看轮选中判断显式发起，沿用既有提交合同。

#### Scenario: 历史结果旁有活动轮
- **WHEN** 用户查看一轮 COMPLETED 历史，另有 QUEUED、RUNNING 或 WAITING_FOR_USER 活动轮
- **THEN** 深入调查和普通发送不可用，草稿保留；取消标明并作用于活动轮，WAITING_FOR_USER 还可补答该轮

#### Scenario: 历史轮继续调查
- **WHEN** 非终态轮为空且用户对已完成历史轮的选中判断显式深入调查
- **THEN** 使用所看轮判断原文、已有合法关联引用及已绑定资产沿现有合同提交，成功后创建新轮并可返回历史，界面不承诺新轮继承原业务时点

#### Scenario: 会话存在多个未决轮
- **WHEN** 如实回读出多个非终态 Run
- **THEN** 提示存在多个未决轮并可逐轮定位；补答或取消绑定可见且明确的非终态目标，普通发送与深入调查保持不可用

### Requirement: 运行事件触发持久状态校准

SSE 事件到达 SHALL 及时更新界面时间线，并在等待通知、终态通知或异常收尾后回读相应 Run 的持久状态。WAITING_FOR_USER SHALL 允许继续原轮，COMPLETED、FAILED、CANCELLED 为终态。断流期间 SHALL 保留有界轮询与重新同步能力，并按 Run 和 seq 去重与续接。

#### Scenario: SSE 先于下一次轮询通知等待
- **WHEN** 本轮收到 RUN_WAITING，下一轮轮询尚未执行
- **THEN** 立即触发持久回读，依据返回的 WAITING_FOR_USER 和实际待答问题更新；无需等待轮询或收到终态事件，补答后仍跟踪原 Run

#### Scenario: 历史查看期间收到活动轮收尾
- **WHEN** 用户查看历史，活动轮收到完成、失败或取消的终态通知
- **THEN** 及时回读活动轮，仅按持久记录更新活动状态、操作及最终结果；历史不被强制切走，事件不混入历史时间线

#### Scenario: 流断线重连与轮询兜底
- **WHEN** SSE 断开后从最后游标续传并重送事件，或流不可用但持久读取仍可用
- **THEN** 相同 Run 的重复 seq 只显示一次，断流不使 Run 变为 FAILED；事件不可用时有界轮询仍更新持久状态，超时保留明确的重新同步入口

#### Scenario: 持久响应交错返回
- **WHEN** SSE 已促成较新版本的持久 Run 回读，随后旧轮询或旧会话刷新才返回
- **THEN** 已知较新状态、消息和提问不回退，切换会话前发出的请求和事件不能写入新会话
