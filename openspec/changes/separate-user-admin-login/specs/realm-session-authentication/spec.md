# Spec Delta

## Purpose

在统一账号存储和密码验证底座上区分业务与管理身份及其登录会话，使两端可以独立认证、退出和撤权，并在保留既有调查、成员关系和审计历史的条件下完成专用管理员接管。

## ADDED Requirements

### Requirement: 账号用途由服务器维护

系统 SHALL 区分 USER 与 ADMIN 账号用途，现有业务账号默认保留 USER。普通注册及用户管理开户 MUST NOT 创建 ADMIN 或写入客户端传入的用途、平台角色。ADMIN SHALL 由可信维护入口创建，不自动获得个人空间、团队成员关系或业务正文访问权。

#### Scenario: 原账号升级
- **WHEN** 在已有业务数据的库上升级账号用途结构
- **THEN** 不改原邮箱、密码、ID、成员关系、调查和引用；已有账号为 USER，不自动把 xie 的业务身份改为 ADMIN

#### Scenario: 创建管理账号
- **WHEN** 可信维护人员以明确授权创建 ADMIN 并授予平台角色
- **THEN** 建立独立账号和审计，不附加业务个人空间；重名邮箱不得覆盖、接管或改写原账号

### Requirement: 两端认证资格分别检查

USER 登录 SHALL 验证 ACTIVE 状态、密码及 USER 用途；ADMIN 登录 SHALL 验证 ACTIVE 状态、密码、ADMIN 用途及 PLATFORM_ADMIN。错误凭据 SHALL 返回一致的 401；仅凭据正确但用途不匹配时返回可识别的入口不匹配结果，且不签发错误端身份。

#### Scenario: 管理账号正确登录
- **WHEN** ACTIVE ADMIN 账号具有平台角色，提交正确管理凭据
- **THEN** 建立管理域会话并轮换该域会话 ID，不修改用户域会话

#### Scenario: 用途与角色不能互相替代
- **WHEN** USER 即使残留平台角色仍尝试管理登录，或 ADMIN 已被撤销平台角色
- **THEN** 前者因用途不匹配拒绝；后者返回 403 PLATFORM_ADMIN_REQUIRED，二者均不能进入管理功能

### Requirement: 会话在服务端绑定登录域

系统 SHALL 独立建立用户域和管理域会话，并把认证域绑定到服务端会话。任何一端的 Cookie、会话 ID 或身份上下文 MUST NOT 被另一端接受；不能仅依赖 Cookie 名称、路径、前端选择或客户端角色。旧业务会话仅能按原业务合同继续使用。

#### Scenario: 普通登录后打开管理端
- **WHEN** 浏览器只有有效业务会话并访问管理资源
- **THEN** 管理接口返回 401，不能凭业务账号的历史平台角色恢复管理身份

#### Scenario: 重命名 Cookie 或跨端复用 ID
- **WHEN** 将用户会话 ID 填入管理 Cookie，或将管理会话 ID 填入用户 Cookie
- **THEN** 两种请求均不能获得目标端身份，不撤销另一端原会话，也不读取另一端资源

#### Scenario: 同浏览器同时使用两端
- **WHEN** 同一浏览器分别以 USER 和 ADMIN 完成对应端登录
- **THEN** 两个身份独立存续，刷新、切页和权限查询不把一端账号写入另一端上下文

### Requirement: CSRF 和退出以当前域为边界

各端 SHALL 使用与该端服务端会话绑定的 CSRF，并在登录后轮换认证状态；跨端令牌和缺失/错误令牌 MUST NOT 完成写入。正常退出及会话过期只影响当前域；账号停用与密码重置仍按账号撤销其全部既有会话。

#### Scenario: 跨端 CSRF
- **WHEN** 使用用户端 CSRF 执行管理登录/写入，或反向使用管理端令牌
- **THEN** 拒绝请求，不创建另一端身份、管理操作或业务记录

#### Scenario: 退出一端后继续另一端
- **WHEN** 两端分别登录后退出其中一端
- **THEN** 退出端旧会话失效；另一端身份、CSRF、未提交表单和正常业务访问不受影响

#### Scenario: 停用及重置
- **WHEN** 某账号被停用或成功重置密码
- **THEN** 撤销该账号全部相关会话和旧凭据，不撤销另一个账号的有效会话；原 Run 持续授权和状态代次规则保留

### Requirement: 每次管理请求持续核验权限

管理请求 SHALL 同时满足管理域会话、ACTIVE ADMIN 用途及当前 PLATFORM_ADMIN；空间知识和 Skill 仍须显式 grant，MANAGE 包含对应 READ。用途或角色撤销 SHALL 在下一次请求生效，不通过前端缓存维持访问。

#### Scenario: 管理员没有空间授权
- **WHEN** 有效管理员访问未获 grant 的空间知识或 Skill
- **THEN** 返回 404 RESOURCE_NOT_FOUND，不泄露该空间资源，不从用户端当前团队推断目标空间

#### Scenario: 撤销管理角色
- **WHEN** 管理会话尚未过期但账号的平台角色已被撤销
- **THEN** 下一次管理调用返回 403，清理该端页面数据；不自动提升其他账号或影响其业务会话

### Requirement: 专用管理员安全接管

切换 SHALL 使用用户指定的新管理员邮箱和明确空间范围，记录创建、角色、grant 与撤权审计。新管理员可登录且拥有所需管理范围后，才允许撤销 xie 的平台角色与原管理 grant；MUST 保留至少一位 ACTIVE ADMIN 平台管理员。不得修改 xie 的业务密码、成员资格或历史作者。

#### Scenario: 接管成功
- **WHEN** 新管理员已完成受控密码设置、管理域登录和指定空间两项管理权限验证
- **THEN** 撤销 xie 的平台角色及两项管理 grant，xie 仍按原邮箱密码登录用户端并访问原业务空间

#### Scenario: 接管失败
- **WHEN** 新账号邮箱冲突、初始密码未设置、登录失败或缺少目标 grant
- **THEN** 不宣称接管成功，不撤销现有唯一平台角色；保留可信维护恢复入口及失败证据

### Requirement: 凭据交付和日志不扩散秘密

密码 SHALL 仅经受控交互或既有安全机制输入并以原口令编码存储，MUST NOT 写入源码、规格、URL、命令参数、日志或聊天。系统 MUST 如实报告未完成的凭据设置和邮件失败，不生成对外可取的管理员注册接口。

#### Scenario: 本机初始设置
- **WHEN** 管理员通过本机可信维护流程设置初始密码
- **THEN** 使用隐藏输入，输出只确认账号用途及操作结果，不回显口令、不代替用户保存密码
