# Design

## Context

详见 [proposal.md](proposal.md)。以下是基于当前代码的基线，旧批次测试只证明当时已覆盖的路径。

| 追踪项 | 当前实现中可复用的部分 | 当前源码缺口 |
| --- | --- | --- |
| 焦点 / 诊断分类 | `claimSelection.ts` 按索引选择，`diagnosisViewModel.ts` 映射类别、确定性和引用，`ClaimDetail.vue` 显示原文 | `ClaimList.vue` 显示原文；`ProfessionalDiagnosisPage.vue` 用 `.pro-grid3` 常驻详情栏，同时平铺摘要和本轮字段 |
| F01 | `GeneralAgentService` 持久化问题、助手消息和 `RUN_WAITING`；`App.vue` 已能从 Run 构造三元组 | 当末条消息等于 `pendingQuestion.question` 时，`App.vue` 隐藏主卡正文，重复正文又在记录抽屉内 |
| F02 | `EvidenceDrawer.vue` 已渲染引用字段，`readReferences` 可查询 Run 归属下的全部登记记录 | 失败/取消分支只改变选中 ID；抽屉仅在完成分支挂载，且 `pro.css` 在 ≤1100px 隐藏其父列。成功分支只用 `result.references`，读取异常折成空列表 |
| F04 | `timeline.ts` 按 generation 隔离回调，`api.ts` 有事件游标、原生 EventSource 重连和 `waitForRun` | `onChange` 只投影 events/live，终态 watch 读取非响应式的 `snapshot()`；流跟随查看轮，历史期间可能错过活动轮通知 |
| F08 | `App.vue` 保留 Run 列表、`pinnedRunId`、`goalMessage` 和 `RunView.asOf` | 最后一轮被当作活动轮，等待归入 UI 终态；资产快照混用输入下拉框；失败/取消读引用前没有清空上一轮；仅按 ID 判断迟到响应，无法区分 A→B→A |

## Goals / Non-Goals

**Goals** — 在现有组件中明确消息提交、活动状态和查看内容各自的归属。所有面向用户的状态可由现有 DTO 和端点验证。

**Non-Goals** — 仅使用现有前端状态、公开 SSE 事件和授权 API。当前设计所需最小后端接口变化为零。若发现现有合同无法提供某项必需数据，在实施前说明证据、建议的最小字段或接口及授权风险，交由本 Change 的审阅者决定。沿用合并的 404 语义、原始结果和现有服务端授权。

## Decisions

### 1. 现有组件内组织单焦点

`App.vue` 持有会话、查看轮、活动轮、自由输入与记录入口。它将所看 `RunView`、按 `goalMessageId` 匹配的 `MessageView`、所看轮的引用状态和 Skill 传给 `ProfessionalDiagnosisPage.vue`。页面组合 `ClaimList`、`ClaimDetail` 和共用 `EvidenceDrawer`。原来的调查记录抽屉继续供逐轮消息、事件及设备快照回看，并承载窄屏的近期调查入口。

桌面采用原型的层级。工作台外层左侧是窄幅「近期调查」和「新调查」入口。任务标题、查看轮与活动轮状态进入顶部浅紫任务卡。任务内用较窄的调查方向导航和占主要宽度的白色焦点面板组织内容。在焦点面板内显示关联证据入口与适用的协作操作，证据详情按需展开。

近期调查复用 `listConversations` 的更新时间顺序、`openConversation`、当前会话标记和现有标题回退；保留加载、空列表与失败反馈。直接用已有会话数据刷新列表，无需为侧栏逐条回读会话详情。以现有 1100px 为布局断点，大于该宽度时侧栏常驻且可独立滚动；达到或低于该宽度时从顶部「查看调查记录」打开同一会话列表，任务区纵向排列，保持输入、来源与状态可达。原型上的演示会话和菜单用于版式参考，页面入口仅绑定现有功能。

视觉以 [专业端原型图](<D:/download/DeviceTruth_商业化产品方案_V0.3_修订包/assets/02_专业用户端.png>) 的浅色紫蓝风格为基线。以 `pro.css` 的专业页容器为范围设置淡蓝灰背景、白色圆角卡片、紫蓝主按钮、淡紫选中态和深色正文。参考 V0.3 §7.1 的 `#6C5CE7` 主色、`#F5F7FD` 背景、`#FFFFFF` 面板和 `#17213D` 正文，按可读性微调。专业组件内的深色硬编码背景改用同组变量，追问、风险、失败与取消保留文字和独立语义色。视觉核对同时检查键盘焦点与窄屏可读性。

调查导航做确定性短预览，沿用原排序，按安全 Unicode 边界截取并添加省略标记。原文保留给中央焦点和完整结果；涉及否定或安全用语的展示仍能在原文核对。完整结果使用现有结构数据按需展开。风险等级、安全处置文案和原始 limitations 默认展示并可换行；本轮建议和不确定点置于独立的本轮信息区。没有 claim 时用本轮摘要或实际空状态。

`diagnosisViewModel.ts` 投影类别和短预览，保留原 `claim.text`、certainty、引用 ID、dataNature 及所有安全条目。知识文档的授权与核验、模拟观测的数据性质均按合同呈现。提交正文仍取原文。现有 `MessageView` 没有普通问题与现场观察的独立类型；在录入动作注明用户报告，记录区保留 USER 原文、时间及未核验语义，避免从文本反推持久化类型。焦点选择和展开均为只读界面交互。

### 2. 引用清单与详情共享一个查看轮作用域

`App.vue` 为每个所看终态轮使用 `GET /api/runs/{id}/references` 回读当前授权下的已登记资料。以 referenceId 逐条保留，不按文档去重而丢失其他章节。单条 claim 的直接引用仍由其原始 `referenceIds` 决定，用此次获准记录按 ID 连接。完整结果保留原字段；证据详情统一经该轮登记列表进入。新请求、切轮或撤权时旧详情退出，加载失败时保留安全重试入口。

| 来源读取结果 | 呈现 |
| --- | --- |
| 未返回 / 正常返回空 | 加载中 / 本轮无已登记来源 |
| 成功列表没有目标 ID | 该引用不存在或已不可用；其余成功获准的来源可用 |
| 401 / 403 或明确授权拒绝 | 无权访问，清空来源内容 |
| 404 或 `NOT_FOUND_OR_DENIED` | 来源不可用或无权访问；服务端刻意合并拒绝和不存在 |
| 网络、服务错误 | 读取失败，可重试；当前轮诊断状态保持 |

抽屉挂载在状态分支之外。使用浏览器原生 `dialog.showModal()` 加工作台现有的抽屉样式，利用原生模态焦点与 Esc 能力。进入时聚焦对话框内元素，关闭恢复到触发按钮；切轮导致触发按钮移除时回到当前任务标题或来源入口。抽屉按 DOM 顺序可操作，在窄屏独立滚动。标题、版本、章节、页码和摘录使用已获准响应，服务端未给出的有效区间、现场核验和下载链接保留未知。

### 3. 查看轮与活动目标分离

查看轮默认沿现有服务器排序跟随最新，手动选择历史时保持固定。活动轮从会话 Run 中筛选 QUEUED/RUNNING/WAITING_FOR_USER，顶部与记录列表分别标出查看和活动状态，支持回到活动轮。若真实返回多个未决轮，标明冲突并列出定位入口；默认展示最近的待答问题（若有），写动作以用户明确选择的活动目标为准。保留单活动跟踪通道，刷新时仍会回读全会话。并发准入由 R0-B 处理。

所看轮资产来自该轮目标消息的 `selectedAssetId`，时点来自该轮 `asOf`。保留 `EvidenceComparison.vue` 的资产读取，在 App 绑定查看轮 ID、资产和时点一起重挂载，避免该组件仅按 assetId 拦截迟到响应时混淆同资产异时点。设备区明确标注请求业务时点，与开始时间、配置记录有效期/记录时间相区分。来源、Skill、历史事件和焦点使用会话/查看轮及读取代次校验，切轮同步清理；每次重试也替换请求代次。深入调查的计划附查看轮 ID，消费计划时再次核对，避免沿用旧焦点。底部资产选择仅供普通提交。

| 持久状态 / 目标 | 操作 |
| --- | --- |
| 无未决轮 | 可自由提交；所看轮 COMPLETED 且有有效选中判断才可深入调查 |
| QUEUED / RUNNING | 保留自由输入草稿并暂停新提交和深入调查；可取消明确的活动轮 |
| WAITING_FOR_USER | 主工作台显示 `pendingQuestion.question` 及字段和轮次，从记录抽屉选轮后可直接回到正文；补答和取消作用于明确的等待轮，现场观察按钮聚焦补答区。字段意外缺失时给出重新同步入口 |
| COMPLETED / FAILED / CANCELLED | 可查看详情和历史；状态本身无取消与补答，取消与补答只针对另行标明的活动轮 |

按钮、Enter 和处理函数共用目标及许可判定。用现有 `replyToQuestion` 发送三元组。过期/不相关或目标缺失的拒绝保留草稿、回读并提示最新问题，补答确认期间沿用原提交保护。草稿在会话/待答目标之间不得串用；同一待答目标发生版本冲突时保留用户可编辑内容。取消等待沿用服务端确认，终态竞争 409 后回读实际状态。无活动轮时，历史深入调查用查看轮资产与受现有上限和授权约束的 `contextRefs`；页面显示历史 `asOf`，此次提交沿用原 API 的默认时点语义。

### 4. SSE 触发回读，持久版本决定状态

`timeline.onChange` 将 `runId/events/maxSeq/live/terminalStatus` 投影为 Vue 响应式快照。复用控制器让 SSE 随活动目标跟踪；查看别轮时，时间线通过现有 `readRunEvents` 读取该轮历史，并按查看作用域校验。活动轮终态收尾后仍可通过既有历史事件读取核对。这样浏览旧结果期间仍可收到活动通知，同时保持一条主实时订阅。

以首次观察到的 `RUN_WAITING` seq、`RUN_TERMINAL` 和流异常为信号合并同一轮回读，依持久 Run 结果更新状态，按需同步会话消息与轮次。重放旧等待事件避免重复回读；活动切换、刷新及补答复用控制器重新对齐。WAITING 停止该段快速轮询并保留非终态身份，流仍可观察后续变化；断流后用既有有界轮询校准排队/运行，等待时支持显式同步与补答后的重新跟踪。连接或轮询超时以可重试的同步提示呈现。

用会话代次拦截旧会话请求，以 Run `version` 合并同轮的轮询、SSE 触发回读和会话刷新；会话详情也按请求代次/会话 `version` 合并消息、忽略明显过时快照。等待与后续执行是合法的版本推进，状态名称不能简单排序。保留 `api.ts` 的 seq 去重、初次历史游标、原生 `Last-Event-ID`，以及 `timeline.ts` 的 generation 防串轮。补答/取消和终态后的异步回读统一处理失败，避免未捕获 Promise 及重复轮询。需要时在 `api.ts` 将现有等待停轮询集合改用对应命名，协议字段和轮询停止条件保持原义。

## Risks / Trade-offs

| 风险 | 处置 |
| --- | --- |
| 完成轮增加一次读取，且授权状态可在两次读取间变化 | 每次进入所看终态轮或显式重试获取登记列表，同一在途请求合并；拒绝后移除可见证据，完整结果与来源详情分开 |
| WAITING 通知重放、SSE/轮询交错、A→B→A 快速返回 | 以 Run ID、seq、会话/查看代次及持久版本校验，用可定时的乱序样本验收 |
| 模态与记录抽屉争夺焦点、窄屏输入或安全文案被遮挡 | 使用统一证据对话框并指定焦点回退，桌面和 390px 键盘实测；另复测穿过现有 1100px 断点 |
| 桌面侧栏挤压焦点，或浅色主题使状态难辨 | 用受限宽度和独立滚动容纳会话列表，以可读文字和语义色表达状态；用浏览器截图对照原型，检查焦点面板宽度、选中态和风险提示 |
| 清理三栏时误删原文或抹去模拟性质 | 同一结果切换前后比对完整字段、风险及来源，使用工业与汽车历史样本 |
| 历史样本中的字段缺失或当前部署制品落后 | 缺失态以已返回字段为准，浏览器记录构建版本、用例数据性质和实际环境 |

## Migration Plan

同一 API 可直接构建部署前端并用已有持久数据验收。回滚使用上一版前端制品，现有 Run、消息和引用可继续读取。

## Open Questions

- 人工审查确认单焦点区的视觉密度、短预览默认长度和完整结果展开控件。当前方案以确定性短预览、窄屏单列及原生抽屉为默认。
- 人工审查确认历史区的“查看轮／活动轮”文案和现场观察入口的提示词。可在保持同样状态与提交目标的前提下调整文案。
