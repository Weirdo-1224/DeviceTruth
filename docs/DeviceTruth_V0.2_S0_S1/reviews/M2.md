## 5. 中文调用链解释（供项目负责人理解新增代码）

1. 入口不变：`POST /api/sessions/{id}/messages` → `ConversationController.message` → `ConversationFlowService.handle`，先由 M1 的 Router + `RouteValidator` 做程序复核（资产白名单、危险词、规则存在性）。
2. QUERY 路径（本轮真正打通）：`ConversationFlowService.query()` 在**同一把会话锁**内做「容量预检 → `QueryService.query(assetId, queryKind)` → 一次性写入 USER+SYSTEM 两条消息」；查询失败或 429 不留半条。
3. `QueryService` 只依赖只读 `AssetRepository`：`ASSET_PROFILE → profile(assetId)`（FACTORY 记录）、`MAINTENANCE_HISTORY → history(assetId, null)`（REPLACEMENT 记录）；每条记录先经 `checked()` 校验 `record.assetId` 与请求一致，不一致抛 `QueryAssetMismatchException` → HTTP 500 固定文案，绝不返回他人数据。
4. 回答内容：正文由记录 `payload` 的 subject/predicate/value 模板化拼接（开发者已在 state.md 声明为模板陈述，非分析结论），`sources[]` 逐项取真实 `evidenceId/sourceRef/sourceType`，`limitations` 固定声明“出厂≠当前装机”“更换≠现场确认”，全程 `SIMULATED`。
5. DIAGNOSE 路径（本轮只映射不执行）：HTTP 仍 501（任何会话写入前抛出）；应用层新增 `planDiagnosis`/`DiagnosisApplicationService.map`：Catalog 给 domain/symptomCode/固定 asOf → `SymptomResolver` 有限别名 → `RouteValidator.hasRule` 用 `RuleRepository.query` 确认规则真实存在 → `DiagnosisGoal.toRequest()` 生成旧四字段 `DiagnosisRequest`（`originalUserMessage` 只留应用层，不进 Core）。该映射由 Reviewer 探针实测正确，供 M3 复用。
