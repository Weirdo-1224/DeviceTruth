# Spec Delta

## Purpose

让专业工作台持续显示调查运行、等待和失败情况，并在断流或刷新后从服务器恢复会话及调查历史。对可恢复队列故障自动补派，对已知末步提交风险准确披露，不将技术失败包装为诊断成功。

## ADDED Requirements

### Requirement: 运行进度与服务端状态一致

工作台 SHALL 展示 QUEUED、RUNNING、WAITING_FOR_USER、COMPLETED、FAILED、CANCELLED 的区别、已有工具/模型事件和已选 Skill。增量事件按 Run 和 seq 去重，切换 Run 后旧请求或事件不得更新当前页。流结束或异常时 SHALL 回读服务端状态；连接失败不等于 Run 失败。

#### Scenario: 断线重连和重复事件

- **WHEN** SSE 短暂断线后重连并重送部分历史事件
- **THEN** 时间线不重复，状态通过服务器回读校准，不重发用户消息

#### Scenario: 追问使事件流结束

- **WHEN** 流以 WAITING_FOR_USER 收尾
- **THEN** 页面回读待答问题并显示补答入口，不将其当作完成答案；补答恢复后重新跟踪原 Run

#### Scenario: 切换历史 Run

- **WHEN** 用户查看历史轮次时旧轮仍有异步请求返回
- **THEN** 当前轮次保持正确，旧返回不覆盖当前结果、引用或时间线

### Requirement: 失败和取消可观察

工作台 SHALL 展示安全失败码及中文说明，区分业务执行失败、提交拒绝和网络等待超时；保留历史消息、事件及已登记证据。取消 SHALL 沿用服务器行为，执行中可显示取消处理中，以回读终态为准；失败后的再次调查 SHALL 是用户显式提交的新轮次。

#### Scenario: 模型失败或等待超时

- **WHEN** Run 返回 FAILED，或页面轮询超时但 Run 尚未终态
- **THEN** 前者展示实际失败码，后者提示连接/等待超时并允许重新同步，不伪造答案或擅自将 Run 置 FAILED

#### Scenario: 执行中取消

- **WHEN** 用户取消 RUNNING 的调查
- **THEN** 页面等待服务器确认取消终态，取消前已存证据和历史仍可访问，终态冲突时回读实际状态

### Requirement: 刷新恢复会话与逐轮结果

工作台 SHALL 从会话列表及会话详情恢复消息、全部 Run 和持久结果，默认查看最新轮次并允许查看旧轮。浏览器可保存会话定位信息，但不得将内存或本地结果作为权威；活动轮恢复跟踪，等待轮恢复问题，失败/取消轮恢复真实状态。

#### Scenario: 多轮调查后刷新

- **WHEN** 一个会话已有两轮完成结果及一轮执行中任务，用户刷新页面
- **THEN** 恢复全部轮次，默认显示最新轮并跟踪执行，仍可查看两轮已完成结果与引用

#### Scenario: 本地定位丢失或无权

- **WHEN** 本地没有会话 ID 或保存的会话不可访问
- **THEN** 从服务器会话列表供用户重新选择或新建，显示安全错误，不显示其他归属的数据

### Requirement: 暂时故障后滞留队列自动恢复

在 worker 启用且数据库恢复可用后，系统 SHALL 有界周期补派因瞬时领取或调度故障遗留的 QUEUED Run，无需重启；重复扫描不能重复执行同一轮。已有有效租约、等待用户及终态任务不应被补派执行，预算和恢复上限继续生效。

#### Scenario: 领取失败后自动续派

- **WHEN** 一个已入库的 QUEUED Run 因临时数据库故障未被领取，随后数据库恢复
- **THEN** 在后续可用扫描周期内自动重新调度并推进状态，不需要用户重发问题或重启服务

#### Scenario: 重复扫描与扫描异常

- **WHEN** 周期扫描重复发现同一 Run，或某次扫描抛出临时异常
- **THEN** 同一 Run 只能有一个有效执行领取，异常后后续扫描仍继续，worker 关闭时不执行补派
