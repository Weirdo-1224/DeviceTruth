# Design

## Context

动机见 proposal。已读 AnswerGuard、AgentResult/AgentTaskInput、StructuredAgentReasoner、TaskOrchestrator 答案/追问分支、AnswerGuardTest 及前端 ViewModel/报告入口。当前 AgentResult.Certainty.CONFIRMED 明确定义为现场确认，Guard 对任何该枚举和命中措辞整份拒绝；主循环固定传 fieldVerified=false，拒绝反馈只有全局 code，一次重答后可能生成通用 HUMAN_REVIEW。现有 verdict 只有 allowed/code/answer，不能表达局部问题和依赖。当前前端只知道类别、claims 和字符串建议，不知道规程参考/执行前提。

主 specs 为空，本次三个 ADDED capability 承接既有最新实现。旧契约中“所有具体操作步骤均拒绝”“所有 CONFIRMED 均要求现场核验”与用户已确认的新规则冲突，作为显式合同替换，不以保留旧断言阻止新行为，也不移除无关安全反例。

## Goals / Non-Goals

**Goals:** 将来源性质、证据支持、对象/时点、结论强度和执行资格分开；产出可拆分且能追踪依赖的答案；在现有有界主循环内完成复核、修正、取消与恢复。

**Non-Goals:** 不控制设备，不新建 Agent 引擎、人员资质平台、规程审批系统或全站管理后台；不自动认领资料，不把检索相关性当真实性，不以分类模型自报绕过硬边界；不随便删改旧 Run 或回算历史答案。

## Decisions

### D1. 排在工作台第 4、5 组之后，第 6 组之前

第四组负责正式输入/讨论/确认的执行段边界，第五组负责附件与发布材料的版本、范围和直接原文访问。本变更消费这些稳定接口，不同时争用 GeneralAgentService/TaskOrchestrator/输入 DTO/知识检索的写所有权。第六组接线前先完成本变更的服务端、结果协议及可复用展示组件；第六组负责空间工作台的页面组合与认证交互。已交付接口即可消费，无须为确认而重开生产者工作。

本变更中与第六组完整页面有关的联合浏览器验收任务须等消费后执行；不能在仅交付后端时勾选整份 change。它不要求先做完现有 change 的 7/8 组，不把语义误拦无限延期。现在仅规划；届时另行 apply，不改另一 change 的勾选状态。

### D2. 整体问题协议 v2，兼容旧结果与检查点

新复核只返回实质 issues：位置、稳定原因码、修正说明、可选来源ID。不列举所有句子、不要求来源性质枚举或逐项支持片段。旧v1结构/结果/检查点继续可读，旧检查点按旧路径完成；新v2检查点保存整份草稿和问题，公开投影不包含原草稿与修正说明。

### D3. 程序硬边界 + 一次整体语义复核

程序检查实际引用子集、资产归属、取消/撤权/迟到和预算；模型只审核关键结论与依据是否一致、引用是否支持说法、是否有无依据高风险具体执行指导。一般解释、低风险调查建议、信息请求、不确定项/限制不强制引用。关键词不否决新版答案。新路径最多一次复核、一次定向修正；修正后做程序硬校验，不再第二次模型复核。复核失败不得视为通过。

### D4. 修正与有限结果

问题定位到原字段供一次修正；修正应保留正确内容，并删除/修复问题和受影响建议及摘要。宿主硬校验修正结果；修正失败或预算不足则明确有限收口，不交付尚有已知问题的草稿。修正成功不自动标有限。原始来源历史保留，最终引用只包含实际答案声明引用。关键问题仍无法回答时明确有限结果。不能通过只把错误确定性结论改成“可能”掩盖缺证。

### D5. 规程与前提迁出

完整原需求迁入add-procedure-grounded-guidance，本变更不实现或宣称已验收规程执行资格。原任务在prior-task-ledger.md保留，不自动勾选。

### D6. 复用现有生命周期、审计和前端能力

复核/修正调用接原模型连接的剩余时间合同，调用前、返回后、工具/最终落库前继续检查取消/撤权。持久保存复核阶段、计数、单元处置和最终结果，重启不重复授予引用/确认、不清零预算。规程前提追问使用原 ASK_USER 与问题三元组，不另建等待状态机；unsafeFollowUp 同步从操作词拒绝改为验证“询问条件”与“诱导操作”的区别。

公开事件/SSE/报告只投影原因类型、单元 ID 和已授权来源定位；完整草稿不放公开事件或普通日志。测试复现草稿只用有界脱敏样本和忽略目录，须明确访问与保留范围。前端 ViewModel、结果组件及报告渲染分开显示参考/条件指导/待确认，不能缩进旧 suggestions 字符串后只加页尾提示；报告不再次调用模型。

## Risks / Trade-offs

- 语义复核误判/自洽错误 → 宿主硬边界独立、正反例成对、模型自报不足以放行；不宣称已证明开放域事实真实性。
- 局部修复破坏依赖 → 结构化单元/依赖闭包/摘要重建，不能拆分则保守整份处理。
- 新字段导致旧页面误显确定性或作业资格 → 版本化可选扩展、保守旧投影、组件合同与历史结果测试，消费前不得开放模糊的高风险指导呈现。
- 高风险开放与旧测试相冲突 → 逐项区分真正改变的合同和应保留反例，变更 ledger 说明理由，不整批删除安全测试。
- 外部复核增加费用和时间 → 单次批量、最多两次复核/一次修正，使用原剩余预算；实测，不无限重试求绿。
- 实际规程材料不足 → 自动化测试标明协议夹具；真实高风险指导验收需合法、可适用的实际材料，缺材料只阻塞对应验收，不能把模拟结果升级。

## Migration Plan

1. 第四、五组交付后读其真实合同、增量 diff 和验证记录；确认单一写所有者再开始，不按当前 V22 硬编码后续迁移号。
2. 先建立旧合同反例与本次补验的拒绝定位；新增版本化字段/存储及安全投影，不改写旧结果。
3. 依次接陈述复核/局部修复、规程与确认、预算/恢复和组件；每段验收后才交付第六组消费。
4. 使用旧入口/历史 Run、真实 PG 并发/撤权/恢复、前端组件和真实模型正反例验证。第六组实际消费后完成联合浏览器验收，再判整份 change 完成。
5. 部署与真实库变更另行授权。回滚须保留新字段和历史记录，用仍理解新合同的兼容程序停止新指导，不能退回匿名或误解新结果的旧程序。
