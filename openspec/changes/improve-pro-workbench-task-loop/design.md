# Design

## Context

当前 Run 的执行上下文和前端设备展示都主要来自目标消息的 `selectedAssetId`，自由文本补答确认的新设备不会同步到任务卡、快照和深入调查。判断合同只有正文、引用与确定性，不能按确定性推断业务类型。会话列表只返回最多 100 个基础会话记录，标题和状态主要由当前前端会话补全。现有报告组件和模型报告工具均未提供面向用户的独立打印交付。

本设计保持 product 与 legacy 隔离、服务端归属校验、只读工具、持久 Run 恢复和真实模型开发默认值。动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 用可持久化、可恢复的 Run 排查对象贯通执行与展示，并兼容旧数据。
- 用结构化业务类型组织结果，前端不猜测文本语义，不虚构摘要、概率或相关性评分。
- 用一次归属受限的汇总查询支撑稳定的会话发现与游标分页。
- 复用同一诊断 ViewModel 形成工作区和报告，避免两处语义漂移。

**Non-Goals:**

- 不通过本次改动提升或承诺模型诊断准确率，不引入语义相关性评分模型。
- 不改变 Agent 单步动作协议、工具只读约束、SSE/轮询状态机和 legacy API。
- 不做公开报告分享、物理删除、用户自定义标题或归档；不新增 PDF、路由或状态管理依赖。

## Decisions

### 1. 排查对象采用 Run 级持久状态，而不是前端推导

在 `dt_agent_run` 增量保存 `subject_asset_id`、`subject_status`、`subject_changed_from`，公开为 RunView 的 `investigatedAssetId`、`assetResolution`、`changedFromAssetId`。状态使用 `SELECTED`、`CONFIRMED`、`AMBIGUOUS`、`UNCONFIRMED`。

- 新 Run 以目标消息的设备初始化；有选择为 `SELECTED`，否则为 `UNCONFIRMED`。
- 补答请求中的结构化设备选择在同一事务内更新 Run，并记录变化来源。执行上下文随后使用该持久对象，不读取“最后一条消息”临时拼接。
- 最终答案增加可选 `subjectAssetId`。AnswerGuard 收集用户显式选择和本 Run 成功资产工具实际访问的候选集合：答案声明与合法候选一致时确认；声明冲突时按无效答案处理并进入既有重试/失败链路；未声明且候选不唯一时保留 `AMBIGUOUS`，不得任选其一。
- 仅读取过某设备不等于用户已经确认；运行中未完成对象核验时展示“设备核对中”，最终只有满足确认规则才显示“已确认”。
- 旧 Run 不回填工具历史。已有目标设备可按 `SELECTED` 展示，其余为 `UNCONFIRMED`，不伪造确认状态。

任务卡、快照、深入调查、会话摘要和报告只读 RunView 的统一字段。`UNCONFIRMED/AMBIGUOUS` 不自动打开设备快照，而是显示待确认原因。

备选方案“取最后一条补答设备”与“取最后一次资产工具参数”都被否决：多资产调查和工具读取顺序都不能代表主排查对象。

### 2. 判断类型与相关性进入结构化答案合同，旧值回退 UNKNOWN

`AgentResult.Claim` 增加 `kind` 与 `relevance`：

- `kind`: `CAUSE`、`OBSERVATION`、`CONCLUSION`、`OTHER`、`UNKNOWN`。
- `relevance`: `DIRECT`、`CONTEXT`、`UNRELATED`、`UNKNOWN`。

新模型输出的 schema 明确要求这两个字段；解析历史 JSON 时缺省为 `UNKNOWN`。AnswerGuard 校验枚举、类别组合和明显矛盾，但不把 `certainty` 映射为业务类型，也不声称能确定性验证模型的语义分类。分类缺失或不合法时不能升级为直接候选原因。

前端 ViewModel 保持服务端原顺序，投影为直接候选原因、背景观测/上下文、其他或未知判断。短结论由答案类别、风险、数据性质和数量确定性生成；长摘要原文保留。建议按服务端原顺序展示前三项，不标记为模型优先级。默认焦点选择第一条 `CAUSE + DIRECT`，没有时显示轮级摘要而不默认选中背景观测。

备选方案“前端按关键词识别胎压/HVAC”和“优先选择 POSSIBLE”都被否决：前者不可维护，后者混淆确定性与业务类型。

### 3. 会话发现使用独立摘要分页合同，保留旧列表接口

新增 `GET /api/conversations/summaries`，支持 `q`、`assetId`、`status`、`cursor`、`limit`，返回 `{items,nextCursor}`。默认每页 20，最大 50；原 `GET /api/conversations` 保留，避免破坏既有调用方。

摘要包含首条用户目标生成的确定性别名、最近排查设备、最新 Run 状态、活动/待答数量、Run 数和更新时间。展示状态优先表达待补答，其次排队/执行，最后表达最近终态。空 Run 会话不进入摘要结果，但不删除。

仓储使用归属过滤的 CTE/聚合查询一次取得目标、Run 汇总和最新对象，禁止逐会话查询。排序以待补答优先、更新时间和 ID 稳定次序组成游标；筛选条件同时作用于游标。必要索引沿用现有归属、会话和时间索引，并在大列表场景检查查询计划。

前端“新调查”只重置本地草稿。首次提交时先创建会话再发送消息；若两步之间失败，保留当前会话与草稿供重试，空会话仍不出现在历史中。附件在草稿阶段保持待随附状态，首条消息提交时绑定，不因选择附件而自动留下空会话。

### 4. 报告与工作区共享投影，打印由浏览器完成

App 增加工作区/报告视图状态，不引入路由。改造 `DiagnosisReport.vue` 接收统一 Run、排查对象、诊断 ViewModel 和已登记引用；打开报告只读取已有持久数据及必要回读，不调用 `generate_diagnosis_report` 或任何模型接口。

报告包含目标、对象变更、状态、业务时点、风险/数据性质、结论、分组判断、建议、人工核验与限制、稳定编号引用及 Run ID。未完成、失败和取消状态只展示实际可用内容，不生成虚构结论。

打印样式隐藏导航、输入和交互控件，保留引用与声明；打印按钮调用浏览器打印，由用户选择打印机或“另存为 PDF”。不同浏览器的分页效果通过真实打印预览验收。

## Risks / Trade-offs

- [模型可能错误声明相关性] → 缺少或矛盾字段回退 UNKNOWN，不自动进入直接候选；保留原顺序和完整原文，并用真实案例检查，不宣称服务端完成语义核验。
- [多资产工具轨迹可能造成对象冲突] → 只有显式选择与合法候选一致才确认，否则拒绝冲突答案或保留歧义；不以最后调用覆盖。
- [新增 Run 状态与答案保存可能不一致] → 对象迁移、答案和状态更新放在现有持久事务与版本控制中，覆盖崩溃恢复和重放测试。
- [摘要聚合与待答优先排序可能增加查询成本] → 单次集合查询、有界分页、稳定游标、归属过滤和查询计划检查，不做 N+1。
- [延迟创建会话会影响上传和失败重试] → 草稿、附件、创建后发送失败分别保留可恢复状态，并补充首提交与重复点击测试。
- [浏览器打印分页存在差异] → 使用简洁打印样式，不以固定分页像素为目标，实际检查 Chromium 打印预览与长引用。

## Migration Plan

1. 先发布增量数据库列与兼容解析；旧数据只设置可证明的初始状态，不重写历史答案。
2. 发布服务端新字段和摘要接口，再发布前端；旧列表接口与既有 Run 字段继续可用。
3. 新结构化答案写入新字段，历史答案始终以 UNKNOWN 回退；报告和工作区共用兼容投影。
4. 回滚时优先回滚前端与服务版本并保留增量列，不执行破坏性数据库回滚。若需要回到不能读取新答案字段的旧后端，必须先停止新结构写入并验证旧解析器兼容性，不直接强制回滚。
5. 按离线测试、真实 PG/真实模型、桌面/移动端与打印预览分别验收，失败或缺环境不得记为通过。
