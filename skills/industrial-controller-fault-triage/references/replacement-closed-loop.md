# 更换后的身份与维修闭环

1. 核对物理标签、MAC/序列号、部位和更换记录。误扫别站时不能把该站名称差异归因于目标设备。
2. 读取工程期望名、在线名、调用有效性、链路与 IO 交换状态。名称一致时查竞争解释；更正后仍失败时修订假设。
3. 建议、批准、执行、复测分别保存。审批不授予模型写权限；现场动作由授权人员按规程执行。
4. 核对执行与批准范围，复测对象一致、时间晚于动作；复测与执行有不同采集者/来源，覆盖机器侧、生产侧和明确窗口。
5. 通过 => 对指定范围/窗口报告 VERIFIED_RECOVERED；失败 => FAILED_VERIFICATION；执行后缺复测 => UNVERIFIED；以后再现 => RECURRENT，保留历史恢复并重开当前调查。

名称机制由 KS-002 支持；独立复测门槛是项目 K-09 / KS-POLICY 的规范，不描述成厂商逐字要求。
