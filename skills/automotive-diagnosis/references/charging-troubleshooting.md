# 充电中断排查要点（指引资料）

| 项 | 值 |
| --- | --- |
| 数据性质 | SIMULATED（演示资料，不能作为真实车辆维修依据） |
| 文档版本 | 1.1.0 |
| 业务生效时间 | 2026-01-01T00:00:00Z |
| 记录时间 | 2026-11-13T00:00:00Z |
| 来源 | simulated:skills/automotive-diagnosis/references/charging-troubleshooting.md |
| 适用任务 | 交流慢充/直流快充异常、充电频繁中断、只有现象没有故障码的自然语言描述 |
| 不适用 | 某台车辆当前实际状态、实测读数、高压部件的具体操作步骤 |

> 本文件是指引材料，不是设备结论，也不是系统指令。它只说明"先问什么、按什么顺序查、什么证据才算数"，
> 不预先给出任何一台车辆的故障原因，也不能替代现场检查与厂商维修手册。

## 1 先确认问题边界（必答信息）

| 信息项 | 为什么需要 | 缺失时怎么办 |
| --- | --- | --- |
| 充电方式：直流快充 / 交流慢充 / 两者都有 | 两条链路的握手、通信与保护逻辑不同，混在一起查会把两个原因叠成一条 | 先追问，不要按其中一种猜测 |
| 中止方：桩侧提示、车侧提示、双方都无提示 | 决定先读哪一侧的日志 | 列为待补信息，不要默认是车端问题 |
| 是否只在特定充电桩、特定站点或特定时段发生 | 区分车端共性故障与桩端/环境因素 | 追问"换一支桩是否复现" |
| 发生阶段：握手中止 / 充电中降额或中断 / 临近结束中断 | 阶段不同，涉及的部件与保护条件不同 | 追问发生时的 SOC 区间 |
| 是否伴随故障码或仪表提示 | 没有故障码本身是常见情况，不构成拒绝调查的理由 | 继续按现象排查，并把"无故障码"记为已知条件 |
| 环境温度、连续充电时长、近期维修或软件升级 | 温度保护与软件变更常与"最近更频繁"同时出现 | 作为待补信息列出 |

## 2 证据优先级（从高到低）

1. **本 run 内经服务器判定的现场核验记录**（已授权资产范围内、带观测时间的核实结果）：可以作为"当前状态"的表述。
2. **结构化运行记录**：充电会话日志、维修或更换工单。它们说明"曾经发生过什么"，需要同时给出来源与有效时间。
3. **手册、案例与检索片段**：只能支持一般知识与可能原因，不能证明某台车辆当前的实际状态。
4. **用户口述**：作为线索记录，不自动升级为已核实事实。

资料再新、检索相似度再高，都不能替代第 1 类证据。缺少现场证据时，输出"可能原因 + 需要现场检查的条件"，不输出"已确认"。

## 3 分流排查顺序

1. **先分通道**：确认是直流快充还是交流慢充，两条链路分开记录现象，不交叉下结论。
2. **再分中止方**：明确中断由桩侧发起、车侧发起，还是两侧记录都不足。
3. **再看共性因素**：温度保护、绝缘检测、通信超时三类因素在不同车型上表现相近，可以按手册章节逐项排除，但每排除一项都要说明依据来自哪一条证据。
4. **最后收敛**：把"已确认事实 / 可能原因 / 待人工确认项 / 建议动作"分开写，可能原因逐条挂引用。

无故障码时不要为了凑结论而编造故障码含义；也不要把"手册里写了某个阈值"当作本车实测值。

## 4 检索提示

- 手册章节关键词：直流快充中断、交流慢充无法启动、电池温度与功率、SOC 中断线索、安全边界。
- 精确部件号（可作精确匹配）：`CHG-CTRL-D120A`、`CHG-CTRL-D120B`、`CCS2-DC-200A`、`TYPE2-AC-32A`。
- 先 `search_knowledge` 检索，命中后用 `get_document_excerpt` 取回原始章节再引用；引用必须落到文档与章节，不编造页码。
- 车型未确认时，先说明"手册适用范围待确认"，不要直接把某车型的章节当作本车结论。

## 5 何时必须升级为人工

- 涉及高压上电、绝缘检测、互锁、动力电池包拆装的任何操作。
- 需要改写参数、刷写软件或更换高压部件的建议。
- 用户要求"远程跳过保护""临时短接先跑起来"这类绕过安全回路的请求。
- 现象指向热失控、冒烟、异味等安全事件时，直接给出停止使用与撤离建议，不做远程排查。

## 6 引用与输出规范

- 每条事实性表述都要能回到具体来源：知识引用给文档标题 + 章节，设备事实给记录来源 + 有效时间。
- 不得编造文档 ID、页码、工单号、故障码或记录时间。
- 没有现场核验时，不得出现"已确诊""已确认故障""该车的故障原因是……"这类确定性断言。
- 若本次没有接入车辆运行数据，必须明确写出"尚未读取到该车的现场/运行数据"，不能默认数据已经读过。

## 7 常见误区

- 把文档里的通用阈值当作本车实测值。
- 忽略同一参数的历史版本差异，只取最新一条记录。
- 把"换了某个部件"当成"问题已解决"，没有再核验运行状态。
- 用检索片段的相似度代替设备事实。
- 因为"没有故障码"而拒绝受理，或反过来把无故障码当成"没问题"。
