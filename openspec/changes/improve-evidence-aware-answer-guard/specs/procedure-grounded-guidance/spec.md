# Spec Delta

## Purpose

使检修人员能够查阅并使用可追溯的作业规程，把适用性、人员和现场前提落实到具体指导内容中。在开放有依据的具体步骤时，避免模型补造流程、遗漏关键条件或把参考材料包装成当前设备已可执行的方案。

## ADDED Requirements

### Requirement: 高风险步骤必须有适用规程
系统 SHALL 允许由适用规程支持的高风险具体步骤。每项动作和参数 MUST 有实际支持的原文与版本，保留顺序、前置条件、警告与停止条件；没有适用规程时不得由模型补写高风险流程。工具仍保持只读。

#### Scenario: 规程和条件适用
- **WHEN** 已取得的有效规程适用于所述型号、配置与作业，必要执行前提已确认
- **THEN** 可展示有定位依据的具体指导，不因出现操作词整份拒绝，且不触发设备控制

#### Scenario: 无规程或只有相近型号
- **WHEN** 仅有通用原理、相近型号或适用性未确定的过期材料
- **THEN** 提供差异、资料需求和低风险调查路径，不将其补成当前设备高风险执行流程

#### Scenario: 步骤引用不支持动作
- **WHEN** 引用存在但不支持草稿的参数、顺序或动作，或草稿漏掉规程关键条件
- **THEN** 不放行该执行指导，保留可以验证的资料说明并定位缺口

### Requirement: 查阅与当前执行指导分别表达
系统 SHALL 区分规程参考和面向当前设备的执行指导。信息不完整时允许查阅原文步骤及其适用条件，但不得仅加页尾免责声明便将其呈现为当前可执行方案。

#### Scenario: 未提供完整设备信息
- **WHEN** 用户查阅规程但缺少关键型号或配置信息
- **THEN** 展示参考用途、原规程适用范围和未知项，不要求先建资产档案，也不声称已匹配当前设备

#### Scenario: 明确不匹配
- **WHEN** 当前设备信息与规程关键适用条件冲突
- **THEN** 不将规程作为当前执行指导，允许解释差异和继续查找正确资料

### Requirement: 用户明确确认前提且保留确认来源
系统 SHALL 按作业询问影响安全执行的人员资质和现场前提；首版允许用户明确确认，不建设独立资质平台。确认 MUST 绑定操作人、对象、作业、时点和规程版本，未知不能默认满足，用户确认不等于系统核验。

#### Scenario: 关键前提尚未回答
- **WHEN** 型号匹配但人员资格或关键现场状态未知
- **THEN** 在相应执行位置暂停并提出具体确认，仍保留规程查阅能力

#### Scenario: 用户确认或明确不满足
- **WHEN** 用户明确确认相关前提，或明确表示不具备资质/条件不满足
- **THEN** 前者作为有来源的条件输入组织指导；后者不继续面向其立即执行的高风险指导，指出停止点及所需条件

#### Scenario: 权限角色或笼统勾选冒充确认
- **WHEN** 用户具有空间管理员角色或仅勾选已阅读风险
- **THEN** 不据此推定专业资质和具体现场条件已满足

### Requirement: 变更和重启不得静默复用失效前提
系统 MUST 将确认与本执行段输入和材料版本绑定。设备、作业、关键配置或规程版本改变时重新判定适用性，不把旧确认当作新场景已满足；重启按原快照恢复，不扫描后加材料改变当前段。

#### Scenario: 旧确认用于新作业
- **WHEN** 用户切换设备或规程版本后继续请求具体步骤
- **THEN** 受影响前提回到待确认状态，旧记录保留但不自动授予新指导资格

### Requirement: 来源性质不因规程展示而提升
系统 MUST 保留模拟、历史、用户提供及许可性质，不把技术索引就绪、发布或用户确认等同于规程真实有效。模拟规程可用于明确标注的参考和测试，不可作为真实现场执行依据。

#### Scenario: 模拟规程参考
- **WHEN** 已取得规程为 SIMULATED
- **THEN** 保留其模拟用途，不展示为真实设备现场可执行指导，也不把管理发布变成现场核验
