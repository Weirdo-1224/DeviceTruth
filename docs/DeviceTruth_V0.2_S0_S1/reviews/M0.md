### 2.1 M0-P1-01 的明确调用链证据

下面是合法动作的示例，路径与文本均为合成标记，不含真实凭据：

```json
{"type":"ESCALATE","reason":"review-only C:\\review-fixture\\context.txt PROMPT_FRAGMENT"}
```

1. `StructuredReasoner.propose()`（`StructuredReasoner.java:53-60`）把符合大小限制的输出解析为 ActionProposal，成功即返回；没有把 reason 限制为枚举或稳定错误码。
2. `ActionProposal.Escalate`（62–63 行）和 `RequestInformation`（55–58 行）只用 `Checks.text` 校验 reason；`Checks.java:10-12` 仅拒绝 null/空白。上述 reason 合法。
3. `TaskOrchestrator.run()` 139/141 行直接执行 `reason=proposal.reason()`；169–174 行把该值写入 `DiagnosisResult.stopReason`，并把结果置入真实 `TERMINATED.data.result`。
4. `spec.md:194` 明确规定摘要为 `运行结束：<outcome>/<stopReason>`，没有对这个非安全码分支提供映射。若照表拼接，示例会成为 `运行结束：ESCALATE/review-only C:\review-fixture\context.txt PROMPT_FRAGMENT`。
5. 这违反同一节禁止绝对路径/模型原始输出的要求；`spec.md:236` 的公开结果字段也需要明确安全规则，避免从结果端点绕过事件过滤。

**风险范围**：用户/证据上下文中出现的路径或片段被模型复述到合法 reason 时，会进入按本契约实现的公开视图。这里不假设模型能访问服务端 Key，也不声称现有 Core 已泄漏 Key。只删掉 JSON 原始载荷并不足以保证派生字符串安全。

**最小修复边界**：仅修订应用层公开视图的契约，说明哪些程序生成的稳定码可展示，REQUEST_INFORMATION/ESCALATE/未知 reason 如何生成固定摘要；真实事件 type、sequence、状态和业务 outcome 保留。原始 reason 可留在既有内部报告。M3 用含合成路径/上下文标记的合法提案验证事件和结果响应不回显。Reviewer 本轮未代改规格、业务代码或测试。

## 5. 中文调用链解释（供项目负责人理解）

本轮没有新增 Java 调用链；确认的是现有 CAR-B 的真实执行链：

1. 用户运行 `java -jar ... --scenario=B --reasoner=scripted`，`DeviceTruthApplication.execute()` 用 `CliOptions.parse()` 校验参数，读取场景 B，得到 CAR-B、COMM_TIMEOUT 和固定业务时刻。
2. `JsonRepositories.fromClasspath()` 加载模拟档案、维修/现场记录和规则；入口手工装配 Gateway、Reasoner、EvidenceManager、DecisionGuard 与 TaskOrchestrator。
3. `TaskOrchestrator.run()` 为这次任务新建 `StateManager`，产生内部 taskId；每轮把最新状态和已取回证据交给 `Reasoner.propose()`。
4. scripted B 的七步是查规则、读出厂档案、建立暂定假设、查更换历史、发现证据、取现场确认、提议决策；Reasoner 只提出动作，真正查询由 Gateway 校验范围后调用 Repository。
5. 出厂记录是 D-120A，更换及现场确认指向 D-120B；`EvidenceManager` 按固定 asOf 重建事实，并使依赖旧配置的假设失效，不能只凭出厂记录当作当前配置。
6. `DecisionGuard` 检查历史/发现/获取记录是否完整、规则和现场证据是否成立；本轮 B 最终允许 DEMO-D-120B，输出 RESOLVED，并由 StateManager 提交第七个状态版本。
7. 编排器把真实结果、状态、证据和事件放入 RunReport；`RunReportWriter.write()` 用另一个 UUID 写四份文件，CLI 关闭 Spring Context 后正常退出。
8. 在线模式只替换提出动作的 Reasoner，仍经过同一 Core；模型失败会产生 Core FAILED 和空 outcome。未来 S1 将从 HTTP 接入该链，本轮尚无 Controller/Service 在运行，尤其不能把尚未实现的事件清洗视为已经安全。
