# DeviceTruth 视觉探索方案

状态：设计探索，尚未浏览器验收。两份 HTML 均为独立模拟原型，不连接产品接口；所有资产、诊断、引用和历史数据均为虚构示例，不能用于实际检修。

## 查看方式

用本机浏览器直接打开 `prototype-a.html` 或 `prototype-b.html`；也可在本目录运行 `python -m http.server 8765`，访问 `http://127.0.0.1:8765/prototype-a.html`。右下角可切换方案。可展开调查步骤和引用、收起证据面板、选择模拟附件和输入模拟追问；这些操作不连接服务器、不保存数据。新调查按钮仅提示为原型。

## 方案比较

| | A：高密度专业工作台 | B：AI Native 交互工作台 |
|---|---|---|
| 主线 | 紧凑任务标题与报告、调查细节 | 强调 Agent 交流、对话气泡与更宽松的阅读节奏 |
| 布局 | 230px 左侧、中央任务区、340px 依据栏 | 205px 左侧、中央对话、350px 浅色依据栏 |
| 风格 | 白色工作区、边框与清晰分组，接近专业工具 | 柔和侧栏、更突出用户消息、以纵向调查线组织过程 |
| 适用 | 同时核查多条记录、偏好紧凑信息的使用者 | 以自然语言问答为主、逐步理解 Agent 行为的使用者 |
| 需要验证 | 工作空间是否显得过密 | 对话留白是否影响长报告阅读效率 |

两方案内容范围一致：会话、用户问题、Agent、工具过程、模拟报告、风险、资料引用、设备冲突和追问。两者目前共用三栏信息结构，主要差异在密度和呈现层次；若需要更激进的布局对比，下一轮应依据实际截图和用户反馈继续拉开结构差异。

## 实际观察与限制

- `frontend/package.json` 提供 `npm run dev`；`frontend/vite.config.ts` 将 `/api` 代理到本机 8080。执行 `npm run dev -- --host 127.0.0.1` 时 Vite 报告 5173 被占用，改用 5174。
- 自动化浏览器访问 5174 超时；随后尝试 `file://` 打开原型，被浏览器安全策略拒绝。后续本机 HTTP 探测返回套接字访问权限错误，尚不能确认 5173 的占用进程或 5174 服务状态。
- 未看到真实产品页面，未截取初始、历史、运行、报告、资产或错误状态；也未对原型做实屏或 1440×900、1920×1080 验收。请勿将原型示例视作真实运行截图。
- 源码审查识别的页面纵向堆叠、引用不直接关联、缺少响应式规则等问题见 `../FRONTEND_UI_AUDIT.md`；实际视觉表现仍待浏览器确认。
- 等待可访问浏览器后，应在两个桌面尺寸检查溢出、对齐、滚动、引用展开、面板切换、键盘焦点，记录截图并复核历史/运行/报错状态；真实后端不可用时只记录空状态，不制造真实结果。
