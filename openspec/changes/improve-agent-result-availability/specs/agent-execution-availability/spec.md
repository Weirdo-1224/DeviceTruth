# Spec Delta

## Purpose

为通用产品 Agent 提供有界、可收口的调查执行能力，在真实模型慢响应、格式错误或部分答案不合法时，仍能基于已取得的真实证据及时交付正常答案或明确标注限制的可用结果。

## ADDED Requirements

### Requirement: 小批量独立工具调查

系统 SHALL 支持模型在一次动作中提出 1 至 3 个相互独立的只读工具查询，并 SHALL 在执行前逐个验证工具授权、参数和依赖关系。现有单工具动作 MUST 保持兼容。

#### Scenario: 批量查询后统一回到模型

- **WHEN** 模型一次提出观测、维修记录和知识检索三个独立查询
- **THEN** 宿主在授权范围内执行这些查询并汇总结果，再进入下一次模型决策，而不是每个查询后分别请求模型

#### Scenario: 批量中存在不合法调用

- **WHEN** 批量动作包含超过上限、未知工具、越权参数或必须先由另一结果确定参数的调用
- **THEN** 系统拒绝不合法部分且不执行越权调用，并通过受控反馈要求模型纠正或缩小批次

### Requirement: 无进展与预算驱动的最终回答阶段

系统 SHALL 将执行分为调查和最终回答两个阶段。连续两个调查轮次没有新增引用且结果重复或为空、仅剩一个步数预算、或剩余时间达到最终回答预留量时，系统 MUST 进入最终回答阶段并禁止新的工具调查。

#### Scenario: 连续空检索后收口

- **WHEN** 连续两个调查轮次均未取得新增引用且没有形成其他有效进展
- **THEN** 系统停止继续检索，并要求基于现有消息、工具摘要和引用形成答案

#### Scenario: 预算接近耗尽

- **WHEN** 调查即将消耗最后一个步数或侵占最终回答预留时间
- **THEN** 系统不再发起新的调查工具调用，并保留最终回答所需的执行预算

### Requirement: 模型请求服从剩余时间

每次模型请求 SHALL 使用单次请求上限与 Run 剩余执行时间中的较小值，并 MUST 在总截止时间后取消等待或拒绝采纳迟到模型内容。协议重试 MUST 使用同一剩余预算，不得重置时限。

#### Scenario: 仅剩少量预算时调用模型

- **WHEN** Run 距离总截止时间只剩 3 秒而单次模型上限为 45 秒
- **THEN** 本次请求最多等待约 3 秒，并进入有限结果收口，不再获得新的 45 秒窗口

### Requirement: 基于真实证据的有限结果交付

系统 SHALL 在已经开展调查但最终模型调用、协议解析或答案审核失败时，使用真实工具摘要和本 Run 引用形成 `HUMAN_REVIEW` 有限结果。有限结果 MUST 标明原失败原因、未形成可靠诊断及数据性质，不得编造候选原因、观测或引用。

#### Scenario: 调查后模型输出持续不合法

- **WHEN** 已有工具执行记录但最终答案两次均不符合协议
- **THEN** 系统交付带原失败原因的 `HUMAN_REVIEW` 结果，而不是仅留下 `MODEL_OUTPUT_INVALID_AFTER_RETRY`

#### Scenario: 尚未开展任何调查

- **WHEN** 首次模型调用即发生不可恢复的配置或传输错误且没有任何工具执行记录
- **THEN** 系统保留真实技术失败，不将其伪装成已经完成的诊断结果

### Requirement: 安全门禁与有限格式容错

系统 SHALL 仅对 Markdown 代码围栏和明确的动作、答案枚举大小写变体做归一化。引用归属、设备对象匹配、未核验不确诊、危险操作拒绝和 `SIMULATED` 保守标记 MUST 对正常答案与有限结果同样生效。

#### Scenario: 安全的格式变体

- **WHEN** 模型返回带 JSON 代码围栏且合法枚举仅大小写不同的单个动作
- **THEN** 系统归一化后继续执行原有严格解析和全部安全校验

#### Scenario: 有限结果包含不安全内容

- **WHEN** 有限结果草稿包含伪造引用、设备不匹配、未核验确诊或危险操作
- **THEN** 系统拒绝该内容并移除相应断言，不得为提高交付率而放行

#### Scenario: 非安全分类组合不再整体失败

- **WHEN** 答案包含 DIRECT 相关性搭配 UNKNOWN 类型，或 UNRELATED 的候选原因
- **THEN** 系统将 DIRECT 的未知相关性降为 UNKNOWN，将 UNRELATED 候选保留为背景信息，不再仅因展示分类组合否决整份答案

### Requirement: 可审计的降级与进展记录

系统 SHALL 记录批量动作、无进展收口、最终回答阶段及有限结果的安全事件和原原因码，且 MUST NOT 保存密钥、完整 Prompt 或模型原始输出。现有 Run 查询和事件接口的字段形状 MUST 保持兼容。

#### Scenario: 用户查看有限结果轨迹

- **WHEN** 一次 Run 在连续空检索后通过有限结果结束
- **THEN** 事件轨迹能够说明无进展收口、最终回答和原失败原因，前端无需新增接口即可展示结果与限制
